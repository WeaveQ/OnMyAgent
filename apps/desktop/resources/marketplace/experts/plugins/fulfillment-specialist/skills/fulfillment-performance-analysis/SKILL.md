# 运输表现分析

把时间与异常记录整理成业务能看懂的问题总结。

## 输入

- 单号、线路、承运方、承诺/实际时间、节点、异常原因；
- 等待、客户反馈（可选）；
- 周报月报模板（可选）。

## 处理

1. 确认周期、准时口径、缺失字段。
2. 能算则算准时率、平均延误、异常比、等待。
3. 按客户/线路/承运商/类型对比。
4. 分开已确认事实与可能原因；导出时工具真写入。

## 输出

- 主要数字与变化；
- 问题集中点与样例；
- 对比表与改进建议要点。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- 需要导出业务表时：用 spreadsheets `write-xlsx` / `extract-sheets` 或 write 工具**真正写入**会话目录，并 `verify`；产物卡才会出现。
- **禁止**只在正文写「已生成 xxx.xlsx」却不调用写入工具。
- **禁止**正文以「已生成 **文件名.xlsx**」开场；先结论与要点，再展开。
- 过程脚本只放 `os.tmpdir()` / `.opencode/tmp/`；不要输出 `文件路径：…`。

## 边界

- 不单票写客户通知 → `customer-update-drafting`
- 不结账、不派车、不报价

# 在途风险识别 / 运输异常与证据

覆盖两类场景：

1. **仍在途**：送达风险、路况与环境风险识别（还没变成事故单）。  
2. **已出问题**：延误/货损/丢失/拒收的时间线与证据缺口。

## 输入

- 进度消息、轨迹/停更、司机反馈、客户催件口径；
- 承诺时效 / ETA / 预约卸货时间（可选）；
- 异常经过、照片说明、各方说法（出险时）；
- 运单、约定、货值/保险、异常模板（可选）。

## 处理

### A. 送达风险识别

1. 对齐：承诺到达窗口 vs 最新节点 vs 剩余动作（在途/等卸/多点）。  
2. 信号：停更时长、失联、节点节奏慢、多点前序延误、冷链异常、进仓排队、预约冲突。  
3. 给出 **低/中/高** 风险 + 触发因素 + 消息/轨迹依据 + 建议动作 + 待核实。  
4. 无足够数据时：标「依据不足」，列最少要补的 1–3 个问题，**不编造一定晚点**。

### B. 路况与在途环境风险

1. 收集：拥堵、事故、管制、封路、绕行、天气、服务区久停、夜间疲劳线索。  
2. 标明每条是 **司机口述 / 轨迹推断 / 用户告知**，无官方来源则写「待核实」。  
3. 估计对 ETA 的方向性影响（可能再晚多久的区间，若完全无法估则说明原因）。  
4. **不做实时导航**，不假装掌握实时路况 API。

### C. 已发生异常与证据

1. 时间线：已确认事实 vs 各方说法。  
2. 材料分类：约定、装卸、包装、现场、路线、签收、损失、沟通。  
3. 证据已有/仍缺；可能原因只写依据。  
4. 下一步：补拍、现场处置、客户口径、内部上报。  
5. 清单导出必须工具真写入。

## 输出

- 风险：等级 · 因素 · 依据 · 动作 · 待核实（可附简表）；
- 异常：时间线 · 材料清单 · 缺口 · 可复制话术；
- 需要时的风险/异常表（产物卡）。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- 需要导出业务表时：用 spreadsheets `write-xlsx` / `extract-sheets` 或 write 工具**真正写入**会话目录，并 `verify`；产物卡才会出现。
- **禁止**只在正文写「已生成 xxx.xlsx」却不调用写入工具。
- **禁止**正文以「已生成 **文件名.xlsx**」开场；先结论与要点，再展开。
- 过程脚本与临时 JSON（如 `oma-summary.json`）只放 `os.tmpdir()` / `.opencode/tmp/`，禁止写会话根；不要输出 `文件路径：…`。

## 边界

- 不擅自定责/赔付金额
- 不结账开票 → 货运财务
- 不派车改派 → 车队管理
- 不报价 → 货运客服
- 不假装实时路况/导航

# 写客户通知和催办消息

把已确认进度写成可复制消息。

## 输入

- 已确认进度、ETA、异常与下一步；
- 接收人（客户/司机/内部）与语气；
- 公司话术与不可承诺项（可选）。

## 处理

1. 分清已发生 / 预计 / 风险 / 未确认。
2. 按场景组织：正常在途、临近到达、延误、等装卸、异常处理中。
3. 明确希望对方做什么；不编造时间承诺。
4. 检查前后时间矛盾与过早定责。

## 输出

- 可复制客户通知 / 延误说明；
- 内部催办或追问司机话术；
- 仍需用户确认的时间与责任说法。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- 需要导出业务表时：用 spreadsheets `write-xlsx` / `extract-sheets` 或 write 工具**真正写入**会话目录，并 `verify`；产物卡才会出现。
- **禁止**只在正文写「已生成 xxx.xlsx」却不调用写入工具。
- **禁止**正文以「已生成 **文件名.xlsx**」开场；先结论与要点，再展开。
- 过程脚本与临时 JSON（如 `oma-summary.json`）只放 `os.tmpdir()` / `.opencode/tmp/`，禁止写会话根；不要输出 `文件路径：…`。

## 边界

- 不替用户发送
- 进度未理清 → 先 `transit-update-structuring`
- 不定责赔付、不结账、不派车

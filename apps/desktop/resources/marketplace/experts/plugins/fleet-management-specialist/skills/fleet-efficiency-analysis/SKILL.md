# 货运调度分析 / 车队效率

两种常见场景：

1. **货运调度分析**（车队表 → 每车怎么用）：今日/明日可派、调度定位、风险注意。  
2. **效率与浪费**（趟次成本数据 → 空驶/等待/闲置）。

## 输入

**调度分析：**

- 车辆司机表、可用时间、位置、车型载重、设备/温区、当前任务；
- 是否只要「今日可派」或含明日预排（可选）。

**效率分析：**

- 趟次、线路、里程、重载/空驶、等待、收入成本（有什么用什么）；
- 统计周期与模板（可选）。

## 处理

### A. 货运调度分析

1. 逐车确认：可用时段、位置、能力（厢长/吨位/方数/尾板/冷链）、任务冲突。
2. 给出**调度定位**示例：干线重货主力、城配/中短途、备选、暂不可派（写清原因）。
3. 汇总：共 N 辆、今日实际可派 M 辆；列出要立刻处理的问题（载重存疑、无冷链、证件/时间冲突等）。
4. 建议表列：车牌 · 车型/厢长 · 可用时间 · 当前位置 · 调度定位 · 注意事项。
5. 导出时 `write-xlsx` 真写入并 `verify`。

### B. 效率与浪费

1. 确认周期、车辆范围、一趟怎么算。
2. 能算则算出车天数、趟数、空驶比、平均等待、装载与毛利口径。
3. 按车辆/司机/线路比较；分开「表内能确认」与「需业务再确认」。

## 输出

- 调度：结论 + 关键发现表 + 立刻处理项（+ 可选 xlsx 产物卡）；
- 效率：排序、问题车/线、缺数、周报要点。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- **必须**用 `write-xlsx` 或 write 工具写出业务 xlsx，产物卡才会出现。
- **禁止**正文「已生成 **车辆与司机调度建议.xlsx**」开场或只喊已生成却不写入。
- 不要 `文件路径：`；过程脚本进 tmp。

## 边界

- 有具体一票订单要配车 → `vehicle-candidate-ranking`
- 派车前全检 → `dispatch-readiness-audit`
- 写司机任务 → `dispatch-brief-drafting`
- 不报价、不盯在途、不结账

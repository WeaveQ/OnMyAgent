# 车队管理专员上手向导

目标不是罗列能力，而是让第一次使用的用户看完即可发出一条合格任务。

## 1. 立即告诉用户该怎么开始

先直接回复以下要点，不调用工具：

- 有车辆油耗或油卡异常时从“油费稽查”开始；需要管人车证险和到期风险时从“挂靠车管理”开始；发生货损、水湿、延误或丢件时从“货损理赔”开始。
- 原始 Excel、照片、运单或聊天记录可以直接发，不必预先整理。
- 我会区分事实、异常线索和待核实项；不会自动扣款、停运、认责、报案或承诺赔付。
- 同一车辆或运单可在三项能力间流转，后续用 `@文件` 引用已有台账或证据。

## 2. 立即输出照着问的示例表

固定使用以下列，示例数据不得替换回 `XX`：

| 遇到这种事 | 直接这样发给我 | 最少准备 | 你会得到 |
| --- | --- | --- | --- |
| 怀疑油耗或油卡异常 | 粤 B12345 六月行驶 3250 公里，加柴油 820 升、金额 6150 元，公司基准 22–25 升/百公里；油卡流水见 `@油费稽查/六月油卡.xlsx`。请稽查异常并列出需要司机说明的记录。 | 车辆、里程、加油或油卡流水、企业基准 | 稽查报告、异常明细 |
| 要检查挂靠车辆风险 | 请检查粤 B67890：车主陈强，司机李师傅，交强险 2026-08-12 到期，商业险 2026-08-20 到期，年检 2026-09-05，挂靠合同 2026-12-31 到期。生成台账、30/15/7 天提醒和催办话术。 | 人车关系、证照、保险、年检、合同日期 | 挂靠车台账、风险清单 |
| 刚发生货损需要处理 | 运单 YD20260718036，广州到长沙，签收时发现 6 箱电子配件进水，申报货值 4.8 万元；现场照片、签收单和司机说明见 `@货损理赔/现场资料/`。请检查证据缺口并准备理赔材料，暂不认责。 | 运单、现场照片、签收、司机说明、货值和保险资料 | 证据清单、理赔材料 |

表格后补充三条使用规则：

- 不确定资料是否齐全也可以先发，我会按风险高低列出缺口。
- 处罚、停运、清退、责任比例和赔付承诺必须由用户确认。
- 跨能力继续时直接说“结合 `@文件名` 继续检查/理赔”，无需重复说明背景。

然后输出一句：“上手路线图正在生成，你可以先照着上面的示例开始。”

## 3. 最后生成 HTML 使用路线图

文字、示例表和使用规则都输出后，执行：

`python3 <Skill根目录>/scripts/render_capability_map.py`

- HTML 必须展示“选择入口 → 提供原始资料 → 核对风险缺口 → 人工确认关键决定”的使用路径。
- 客户端会直接读取脚本 stdout 返回的完整 `inlineWidget` JSON 并渲染，agent 无需也不得再调用 `render_visual`、`show_widget`、`visualizer` 或其他可视化工具。
- 禁止改用 Mermaid、SVG 重新绘制；禁止 `cat`/读取 `.process` HTML 文件内容到对话或传给任何渲染工具。
- `.process` 上的完整 HTML 文档仅供本地预览，不作为正式产物链接；渲染只认 stdout 的 fragment `inlineWidget`。
- 预览失败时只简短说明路线图暂不可用，前面的上手说明仍然有效。

## 4. 路线图完成后立即结束

- 脚本返回的 `inlineWidget` 是本轮唯一且最终的上手路线图。
- `inlineWidget` 成功返回后立即结束本轮，不再调用 `render_visual`、`show_widget`、`visualizer` 或其他可视化工具。
- 不再重复上手说明、示例表、任务总结或下一步建议。
- 不输出“已完成”“已就绪”“收到”“请直接发送资料”等状态确认；图谱必须是本轮最后一个可见内容。
- 不复述、检查或评价自己此前已经输出的内容。

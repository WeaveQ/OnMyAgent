# 整理车辆和司机表

把分散的车辆和司机资料整理成调度能直接看的表。本技能只做**合并与标注**，不替代调度分析、挑车或派车前检查。

## 输入

- 车辆、司机、证照保险、当前位置、当前任务等文件或描述；
- 用车牌还是司机手机号对齐（可选）；
- 用户车队表模板（可选）。

## 处理

1. 统一车牌、司机姓名、车型、载重、日期和状态写法；载重单位/数值异常标「存疑」。
2. 按车牌或手机号合并同一主体，保留来源与更新时间。
3. 标出重复、冲突、缺项、证件过期、很久未更新。
4. 分成「可以拿来调度 / 还要补资料 / 暂时不能用」。
5. 标准 CSV 可用 `scripts/consolidate_fleet.py` 批量合并。
6. 需要导出业务表时：用 spreadsheets `write-xlsx` 或 write 工具**真正写入**会话目录；`verify` 后再在正文用表格呈现要点。

## 输出

- 整理好的车辆司机表（正文表格 + 需要时的 xlsx 产物卡）；
- 重复、冲突、缺少、过期清单；
- 哪些车可直接用于后续调度分析。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- 禁止只写「已生成 xxx.xlsx」却不调用写入工具。
- 禁止正文以「已生成 **文件名**」开场；先结论/表格。
- 过程脚本与临时 JSON（如 `oma-summary.json`）只放 `os.tmpdir()` / `.opencode/tmp/`，禁止写会话根。
- 不要输出 `文件路径：…`。

## 边界

- 不做多车调度建议全文 → 用「货运调度分析」能力 / `fleet-efficiency-analysis`
- 不按单挑车 → `vehicle-candidate-ranking`
- 不做派车前检查、不写司机任务
- 不报价、不盯在途、不结账

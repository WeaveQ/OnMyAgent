# 返点协议三方核对

**不默认绑定某一种开票表 / 计划单 / 协议版式。** 先读真实文件结构，再映射字段；默认列名只是启发式，映射不对时用 `--column-map` 或人工确认；版式过于特殊时再写当次辅助脚本。

## 输入

三类材料（本地文件即可）：

1. 开票申请 Excel（一份或多份）
2. 返点协议 PDF / DOCX（一份或多份）
3. 项目计划单 Excel（一份或多份）

可选：列名映射、计划单 sheet 名、金额容差（默认 ¥1）。

## 处理流程（强制）

### 1. 发现

- 用 `document-processing` / `officecli` 打开样例文件，列出实际表头、sheet、协议关键字段
- 与下方「逻辑字段」对齐，产出映射草案；**一次**列出缺失与歧义项并请用户确认

逻辑字段（业务含义，不是固定列名）：

| 逻辑侧 | 常见列名线索（非穷尽） |
|--------|------------------------|
| 发票抬头 / 主体 | 发票抬头、甲方、公司名称 |
| 税号 | 税号、统一社会信用代码 |
| 开票金额 | 开票金额、金额 |
| 发票类型 / 开票内容 | 发票类型、开票内容 |
| 达人 / 返点 | 达人、博主、渠道服务费、返点金额 |

### 2. 核对规则

1. 开票申请 ↔ 协议：按主体/抬头匹配，核税号、金额、类型、内容  
2. 协议 ↔ 计划单：按达人名称匹配，核渠道服务费 / 返点金额  
3. 保留来源文件、行/表位置和金额差异  
4. 多协议候选、重复达人、模糊匹配、材料缺失 → **不得**默认取第一条，统一「需人工确认」  
5. 金额容差写入摘要（默认 ¥1，可改）

### 3. 执行

优先在确认映射后调用脚本：

```bash
python3 scripts/check_rebate_contracts.py \
  --invoice-folder 开票申请目录 \
  --contract-folder 返点协议目录 \
  --plan-folder 项目计划单目录 \
  --output 返点合同核对报告.xlsx \
  --amount-tolerance 1 \
  --column-map mapping.json
```

- `column-map`：逻辑字段 → **实际表头**（或表头列表）；表头与默认不符时**必须**提供  
- `--plan-sheet`：计划单工作表名；不存在时脚本会尝试其它 sheet，仍找不到则进待办  
- PDF 正文结构差异大时：优先 `document-processing` 提取关键字段后并入核对；通用解析不够再写当次辅助提取

## 输出

- `核对清单`：逐条字段、来源、差异、结果  
- `核对摘要`：容差、通过 / 不通过 / 未找到 / 需人工确认  
- `待处理事项`：缺失、冲突、重复、模糊匹配  

## 边界

- 不替代财务、法务、税务终审  
- 不自动提交开票、签署或修改源文件  
- 金额容差必须在报告中展示  
- 不假设所有项目都用「推广计划单-立项及结案PM更新」等固定 sheet 名  

## 依赖与降级

脚本依赖 `openpyxl`、`pdfplumber`。缺失时明确提示使用产品文档处理环境，不静默安装。OfficeCLI 可用于读 xlsx/docx；PDF 仍走 pdfplumber / document-processing。

# 通用审核 Prompt 模板（小红书脚本审核）

> 本文件是 `xhs-script-assistant` skill 的**标准审核指令层**。
> 双重用途：
> 1. 作为 skill 内部审核逻辑基准——标准/批量审核时，判断标准与输出表以本模板为准。
> 2. 作为**独立通用 Prompt**——直接复制粘贴给任意模型（脱离 WorkBuddy/skill）也能产出合规审核；但会失去 `extract.py`/`缓存 Brief`/`docx-template.py` 的成本优势。
>
> 与 skill 原有机制的关系：本模板的「6 维判断标准」≈ 原 14 项审查的上位归类；「6 字段问题表」≡ 原「修改说明表 + 风险表达表」的合并升级版（新增风险等级 P0/P1/P2 + 可替代表达列）。

---

## 背景

这是一个小红书达人种草项目，产品是【产品名称】，目标人群是【目标人群】，本次内容方向是【内容方向】。

客户重点希望突出【核心卖点】，同时需要避免【禁用表达/风险点】。

修改强度（未指定默认中修）：【轻修 / 中修 / 重修】

---

## 输入材料

1. 达人脚本：【粘贴脚本】
2. 客户 Brief：【粘贴 Brief 重点】
3. 产品卖点：【粘贴产品卖点】
4. 参考内容 / 禁用词：【如有则粘贴】

---

## 硬约束（必须遵守，不可突破）

- **时长/字数**：视频时长【X–Y 秒】，口播字数上限约【Z 字】；超出即 **P0**。
- **平台禁区兜底**（即便 Brief 未列也生效）：医疗化（治疗/消炎/抗菌/防癌）、绝对化（最/第一/唯一/100%）、功效过满（拉满/秒杀/根治）。
- **禁止编造**：不得自行新增产品未提供的功效、成分、数据或活动信息。

---

## 判断标准（6 维）

1. 卖点是否清晰
2. 痛点和场景是否成立
3. 种草逻辑是否顺畅
4. 表达是否自然、有真实感
5. 是否存在平台风险或功效夸大风险
6. 是否符合客户 Brief 要求

---

## 输出格式

### ① 修改后脚本（含留痕）

保留我方脚本模板结构（序号 / 时间 / 画面 / 口播 / 花字）。

留痕格式：
- 删除：`~~被删除的内容~~`
- 新增：`<span style="color:red">新增内容</span>`
- 替换：`~~原表达~~ <span style="color:red">新表达</span>`
- 大段重写：段前标注 `【此段因：Brief偏离 / 功效风险 / 结构不符 / 表达过硬 / 客户偏好，已重写】`

### ② 审核核对问题表（6 字段，必输出）

| 问题位置 | 问题类型 | 具体问题 | 风险等级 | 修改建议 | 可替代表达 |
|---|---|---|---|---|---|

**风险等级定义：**
- **P0**：不改不能发（偏离 Brief / 超时 / 医疗化 / 绝对化 / 编造功效）
- **P1**：强烈建议改（夸大表达 / 植入过硬 / 漏必提卖点 / 缺搜索引导 / 竞品拉踩）
- **P2**：表达优化（口语化 / 节奏 / 结构 / 原生感不足）
- **需人工复核**：不确定是否违规时标注此旗标，不自行判定。

### ③ Brief 符合度速查

| Brief 要求 | 满足 / ⚠️缺失 | 对应位置 | 备注 |
|---|---|---|---|

---

## 注意事项

1. 不确定是否违规的地方请标注"需人工复核"。
2. 不要自行新增产品没有提供的功效。
3. 不要把表达改得过于广告化。
4. 修改建议要尽量保留达人原本的表达风格。
5. 修改强度遵守：轻修只动风险/错漏；中修可调整结构与植入；重修需说明原因方可全盘重写。
6. 输出前自检：开场有抓点、无 AI 腔书面连词、卖点有场景支撑、无最高级/未证实数据、结尾有轻引导。

---

## 与 skill 批量流程的对接（仅 skill 内使用时参考）

- 批量审核时，①修改后脚本 → `script_rows`；②问题表 → `issue_rows`（6 字段）；③符合度 → `brief_check_rows`。
- 调用 `references/docx-template.py` 渲染：`python3 docx-template.py --batch <batch.json> <输出目录>`，每个达人生成 `<项目名>_<达人名>_审核.docx`。
- 风险等级列直接写 `"P0"/"P1"/"P2"`，模板脚本自动着色。

# 返点合同三方核对使用指南

## 输入

1. 开票申请 Excel：至少能映射出发票抬头、税号、开票金额、发票类型、开票内容（列名因项目而异）。
2. 返点协议 PDF/DOCX：协议主体、税号、渠道服务费/返点金额、发票类型、开票内容及达人明细。
3. 项目计划单 Excel：结算区中的达人名称与返点金额；sheet 名不固定，可用 `--plan-sheet` 指定优先表。

所有输入均从本地文件读取，不要求登录或连接外部平台。**不要假设只有一种客户模板。**

## 核对规则

- 发票与协议：公司、税号、金额、发票类型、开票内容。
- 协议与计划单：达人名称、达人返点金额。
- 默认金额容差为 ¥1；可通过 `--amount-tolerance` 调整，并会写入摘要。
- 任一关键字段缺失均进入待处理事项。
- 同一公司匹配到多份协议、公司名只能模糊匹配、同一达人存在多条计划记录时，不默认取第一条，统一标记“需人工确认”。

## 命令

先对照真实表头写映射，再跑脚本：

```bash
python3 scripts/check_rebate_contracts.py \
  --invoice-folder 开票申请目录 \
  --contract-folder 返点协议目录 \
  --plan-folder 项目计划单目录 \
  --output 返点合同核对报告.xlsx \
  --amount-tolerance 1 \
  --column-map '{"发票抬头":["发票抬头","公司名称"],"税号":["税号","统一社会信用代码"],"开票金额":"开票金额"}'
```

脚本依赖 `pdfplumber` 和 `openpyxl`。缺少依赖时会给出可理解的错误，不会修改系统 Python 或自动安装全局依赖。版式差异大时优先 `document-processing` / OfficeCLI 辅助读表；仍不够可写当次辅助脚本。

## 输出

- `核对清单`：逐条对照值、来源、差异和最终状态。
- `核对摘要`：金额容差、总记录数、通过、不通过和需人工确认数量。
- `待处理事项`：所有未通过、缺失、重复或模糊匹配记录。

报告只能作为业务初核，金额、主体、税号、合同和开票结论必须人工复核；工具不会签署协议、开票或提交材料。

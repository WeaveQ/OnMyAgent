# 提报完整性与交接检查

## 输入

- 提报名单、Brief、达人数据、报价档期台账；
- 客户检查清单或提报模板（可选）。

## 处理

1. 检查目标、人群、卖点、达人要求、交付、排期和禁用表达是否有来源。
2. 检查每位达人是否有分级理由、报价、档期、交付形式和未决事项。
3. 将问题按“阻塞提报、建议补充、可后补”分级。
4. 生成媒介 → 达人运营交接包，明确已确认和待确认边界。

## 输出

- 提报检查表：位置、问题、级别、来源、建议动作；
- 可提报/需补充后提报结论；
- 交接包：九字段 Brief、已选达人、报价排期、必提卖点、禁用表达、客户偏好、待确认项、来源。

## 边界

- 不替用户发送提报或确认达人；
- 不把历史案例当作当前客户确认；
- 不做脚本终稿或合同签署。

## 文件交付

需要导出材料时使用 `document-processing`，保留用户模板并验证产物。

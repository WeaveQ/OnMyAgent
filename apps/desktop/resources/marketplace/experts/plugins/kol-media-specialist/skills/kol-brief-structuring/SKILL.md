# Brief 拆解与结构化输出

把客户/品牌方发来的原始 Brief 变成可执行的结构化表，方便对频与提报。

## 输入

- 原始 Brief（文本、截图、PDF/Word/表格均可）；
- 用户参考模板或历史好例子（可选，**优先**）；
- 品牌/品类/预算/平台补充说明（可选）。

## 处理

1. 抽取：项目目标、核心需求、交付物、时间节点、预算/KPI、平台与内容形式、已明确事项。
2. 标出待确认问题与风险点（信息缺口、冲突表述、合规敏感点、不可执行处）。
3. 给出下一步动作（需向客户确认 / 内部准备）。
4. 无模板时默认表格字段：目标｜核心需求｜已明确｜待确认｜风险｜下一步｜来源摘录。
5. 有模板时严格映射到用户字段，不擅自增删主结构。

## 输出

- 结构化 Brief 表（主交付）；
- 待确认问题清单（可直接发出的补问稿可选）；
- 风险与下一步。

## 边界

- 不做达人筛选与报价谈判 → 用达人筛选 / 人工商务
- 不替用户对外发送 Brief 确认
- 无依据不编造客户未写的 KPI 或预算


## 模板优先（强制）

1. 用户提供了模板文件、示例文件，或在对话中给出示例结构 → **严格按用户结构、字段顺序、标题与表述风格输出**；输出开头标注：`已严格按您提供的模板/示例输出`。
2. 用户未提供任何模板/示例 → 使用本技能默认最佳实践结构；可标注：`按默认最佳实践输出`。
3. 用户模板与内部模板冲突时，**用户提供的永远优先**。
4. 多模态输入（PDF / Word / Excel / 图片截图等）先完成解析与理解，再进入上述逻辑。

## 文件交付

- 需要导出业务表/文档时：用 `document-processing` + spreadsheets `write-xlsx` / `write` **真正写入**会话目录并 `verify`，产物卡才会出现。
- **跟进轮同样必须真写入**；禁止只在正文宣称「已生成」；禁止 `文件路径：`；临时 JSON 只放 `os.tmpdir()` / `.opencode/tmp/`。
- 正文用粗体标文件名；先结论后展开。

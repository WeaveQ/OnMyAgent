# 九字段 Brief 拆解

## 输入

- 客户原始需求、Brief、截图或会议记录；
- 当前项目模板、历史同类项目或知识库材料（可选）；
- 客户明确补充说明。

## 处理

1. 以当前客户要求为准，历史案例只补充结构，不覆盖当前要求。
2. 固定检查：种草目标、目标人群、产品卖点、内容方向、达人要求、交付形式、时间节点、待确认问题、风险点。
3. 为每项记录原文件、页码、表名或文字位置；无依据内容写“待确认”。
4. 将缺失项转成可以直接用于内部对频的建议动作。

## 输出

- 默认表：`模块｜已明确内容｜待补充信息｜建议动作｜来源`；
- 待确认问题清单；
- 可交给达人运营的卖点、禁用表达、交付和排期摘要。

## 边界

- 不编造预算、达人数量、KPI 或交付周期；
- 不替用户向客户发问或确认；
- 用户提供模板时严格沿用其字段和顺序。

## 文件交付

需要生成 Word 或 Excel 时：

1. 将最终文件写入当前专家会话 cwd，上传 inbox 只读；
2. 提取文本、历史材料摘要、JSON 和辅助脚本只放 `.opencode/tmp/` 或 `os.tmpdir()`；
3. 使用 `document-processing` 实际写入并验证文件可打开；
4. 只对最终 Word / Excel 打印 `ONMYAGENT_DELIVERABLE: <相对路径>`，标记必须是单独一行的纯文本，不得加粗、放进列表、代码块或表格；过程文件不登记。

用户要求 Word 时，不能只在正文给九字段表；必须实际生成包含九字段表、待确认问题、媒介 → 达人运营交接摘要和当前事实/历史经验冲突说明的 Word。

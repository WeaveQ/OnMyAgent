# 达人筛选与分级推荐

在达人池中做分级推荐，输出可提报的名单逻辑。

## 输入

- 达人列表/主页数据/表格（粉丝、垂直度、互动、报价、历史合作等）；
- 品牌调性、目标人群、内容方向、平台、预算带；
- 用户筛选模板或历史提报示例（可选，**优先**）。

## 处理

1. 硬过滤：品类不符、明显虚假数据、高危/黑名单迹象、预算明显超限。
2. 软排序：人设匹配、内容垂直度、互动质量、商业痕迹、内容安全风险。
3. 分成 **优先推荐 / 可备选 / 不建议**，逐人写理由与仍需确认项。
4. 资料不足时标明缺什么，不凑数推荐。
5. 导出提报表时真写入 xlsx。

## 输出

- 三类分级清单 + 理由；
- 建议提报顺序与风险备注；
- 可选提报表文件。

## 边界

- 不做合同签署、不代下单
- 不编造粉丝/互动/报价数据
- 不替代合规终审与客户最终拍板


## 模板优先（强制）

1. 用户提供了模板文件、示例文件，或在对话中给出示例结构 → **严格按用户结构、字段顺序、标题与表述风格输出**；输出开头标注：`已严格按您提供的模板/示例输出`。
2. 用户未提供任何模板/示例 → 使用本技能默认最佳实践结构；可标注：`按默认最佳实践输出`。
3. 用户模板与内部模板冲突时，**用户提供的永远优先**。
4. 多模态输入（PDF / Word / Excel / 图片截图等）先完成解析与理解，再进入上述逻辑。

## 文件交付

- 需要导出业务表/文档时：用 `document-processing` + spreadsheets `write-xlsx` / `write` **真正写入**会话目录并 `verify`，产物卡才会出现。
- **跟进轮同样必须真写入**；禁止只在正文宣称「已生成」；禁止 `文件路径：`；临时 JSON 只放 `os.tmpdir()` / `.opencode/tmp/`。
- 正文用粗体标文件名；先结论后展开。

# 检查缺项并写补问话术

在报价或建单前，一次找齐真正卡住下一步的信息。本技能做**齐全度判断 + 补问**，不重做整表整理，也不算价。

## 输入

- 已整理的发货表，或原始聊天/截图/文件；
- 下一步目标：询价、报价、录单，或整理后交给车队；
- 公司必填要求或检查模板（可选）；
- 已知场景：专线/干线/城配/冷链/3PL（可选）。

## 处理

1. 按下一步目标区分：现在必须有 vs 可以后补。
2. 对照通用必填：发收货人电话与可定位地址、品名包装、件数、重量/体积、时效、付款方式。
3. 场景必查：
   - 冷链：温度区间、全程冷链、记录仪
   - 专线：班期/截单、到站方式
   - 城配：卸货顺序、时间窗、尾板/搬运
   - 3PL：入库/贴标/分拣等
4. 问题归类：`缺少 / 前后对不上 / 说不清 / 需业务确认`，并写清会影响什么。
5. 高风险缺失优先标出：地址只有城市、吨方不全、品名模糊、时效只说“尽快”、冷链无温度、城配无顺序/时间窗、付款不明。
6. 合并成**一次**提问，写一段可直接发给客户的补问消息。

## 输出

- 结论：现在能不能继续询价/报价/录单；
- 已确认 / 还缺 / 对不上（按重要性）；
- 一段客户补问话术；
- 可选：按用户模板整理的检查结果表。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- 需要导出业务表时：用 spreadsheets `write-xlsx` / `extract-sheets` 或 write 工具**真正写入**会话目录，并 `verify`；产物卡才会出现。
- **禁止**只在正文写「已生成 xxx.xlsx」却不调用写入工具。
- **禁止**正文以「已生成 **文件名.xlsx**」开场；先结论与要点，再展开。
- 过程脚本与临时 JSON（如 `oma-summary.json`）只放 `os.tmpdir()` / `.opencode/tmp/`，禁止写会话根；不要输出 `文件路径：…`。

## 边界

- 表还很乱时，先「整理发货信息」再查缺项
- 不编造报价、不对系统订单
- 不替用户对外发送补问消息

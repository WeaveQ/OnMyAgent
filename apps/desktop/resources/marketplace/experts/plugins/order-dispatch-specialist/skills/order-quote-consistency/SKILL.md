# 核对订单有没有写错

在提交订单或交给车队前，找出会导致少收钱、现场做不了或事后扯皮的差异。本技能做**交叉核对**，不重新整理全表，也不重算报价方案。

## 输入

- 客户最终确认（聊天/邮件/文件）；
- 报价消息或报价单；
- 合同/长期协议、系统订单或运单草稿（有什么对什么）；
- 用户检查模板（可选）。

## 处理

1. 逐项比对：线路、发收货、货物吨方、时效、服务内容、价格税费、回单、付款。
2. 场景字段一并比：冷链温度/全程冷链/记录仪；专线班期/到站方式；城配多点顺序/时间窗/尾板；3PL 增值服务。
3. 标注：`一致 / 疑似同义待确认 / 明确不一致 / 来源不明`。
4. 说明每个差异可能造成：少收费用、派车困难、现场返工、温控争议、对账争议。
5. 给出处理建议：改订单 / 再问客户 / 内部确认；**不直接改业务系统、不替用户提交**。

## 输出

- 一致项与差异清单（按风险排序）；
- 每项影响与建议改法；
- 提交前还须确认的点；
- 一段可发给客户或内部审批的确认话。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- 需要导出业务表时：用 spreadsheets `write-xlsx` / `extract-sheets` 或 write 工具**真正写入**会话目录，并 `verify`；产物卡才会出现。
- **禁止**只在正文写「已生成 xxx.xlsx」却不调用写入工具。
- **禁止**正文以「已生成 **文件名.xlsx**」开场；先结论与要点，再展开。
- 过程脚本只放 `os.tmpdir()` / `.opencode/tmp/`；不要输出 `文件路径：…`。

## 边界

- 报价怎么定 → 用「计算报价」
- 信息缺不缺 → 用「检查缺项」
- 挑车派车 → 车队管理专家；在途回单 → 物流运输专家；结账开票 → 货运财务专家

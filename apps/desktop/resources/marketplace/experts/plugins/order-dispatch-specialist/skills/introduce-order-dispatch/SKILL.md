# 接单调度专员上手向导

目标不是罗列能力，而是让第一次使用的用户看完即可发出一条合格任务。

## 1. 立即告诉用户该怎么开始

先直接回复以下要点，不调用工具：

- 把客户的微信、语音转写、询价或待调度订单原样发来，不必先整理。
- 需要出单时从“物流单”开始；客户问价时从“报价”开始；订单已确认、需要找车时从“运力调配”开始。
- 缺失信息会一次性集中追问；报价发送和最终锁车仍由用户确认。
- 同一会话可以连续完成“录单 → 报价 → 调度”，后续能力可用 `@文件` 引用前一步产物。

## 2. 立即输出照着问的示例表

固定使用以下列，示例数据不得替换回 `XX`：

| 遇到这种事 | 直接这样发给我 | 最少准备 | 你会得到 |
| --- | --- | --- | --- |
| 客户发来零散发货信息 | 客户微信发来：“明天上午 9 点从苏州相城发 36 箱汽车配件到杭州余杭，约 2.8 吨、12 方，要 6.8 米厢式车，收货人王师傅 13800001234，到付 1650 元。”请生成物流单并列出待确认项。 | 原始消息、图片或语音转写 | 物流单、待确认项 |
| 客户正在询价 | 苏州相城到杭州余杭，汽配 8 吨 / 32 方，9.6 米厢车，次日达，含税、回单和装卸；企业成本 1800 元。请给最快、平衡、最便宜三档报价并检查底价。 | 线路、吨方、车型、时效、附加服务、企业成本 | 三档报价、底价提醒 |
| 已有订单需要找车 | 上海松江到宁波北仑，五金 12 吨，今天 14:00 装货；可用车辆见 `@运力调配/车辆池.csv`。请筛选 1–3 辆候选车，列出淘汰原因，暂不锁车。 | 订单要求、车辆实时状态 | 候选车辆、调度方案 |

表格后补充三条使用规则：

- 信息不全也可以先发，我会只追问影响出单、报价或派车的关键缺项。
- 涉及客户报价、锁车、改单或对外发送时，我会停下来让你确认。
- 继续下一步时直接说“用 `@文件名` 继续报价/调度”，无需重复录入。

然后输出一句：“上手路线图正在生成，你可以先照着上面的示例开始。”

## 3. 最后生成 HTML 使用路线图

文字、示例表和使用规则都输出后，执行：

`python3 <Skill根目录>/scripts/render_capability_map.py`

- HTML 必须展示“选择入口 → 提供原始资料 → 确认关键缺项 → 获得产物”的使用路径。
- 客户端会直接读取脚本 stdout 返回的完整 `inlineWidget` JSON 并渲染，agent 无需也不得再调用 `render_visual`、`show_widget`、`visualizer` 或其他可视化工具。
- 禁止改用 Mermaid、SVG 重新绘制；禁止 `cat`/读取 `.process` HTML 文件内容到对话或传给任何渲染工具。
- `.process` 上的完整 HTML 文档仅供本地预览，不作为正式产物链接；渲染只认 stdout 的 fragment `inlineWidget`。
- 预览失败时只简短说明路线图暂不可用，前面的上手说明仍然有效。

## 4. 路线图完成后立即结束

- 脚本返回的 `inlineWidget` 是本轮唯一且最终的上手路线图。
- `inlineWidget` 成功返回后立即结束本轮，不再调用 `render_visual`、`show_widget`、`visualizer` 或其他可视化工具。
- 不再重复上手说明、示例表、任务总结或下一步建议。
- 不输出“已完成”“已就绪”“收到”“请直接发送资料”等状态确认；图谱必须是本轮最后一个可见内容。
- 不复述、检查或评价自己此前已经输出的内容。

# 计算并建议报价

把已有成本和价格算清楚，给出能继续确认的报价建议。**无成本/价格依据时不编造数字**，只说明还缺什么。

## 输入

- 线路、货物吨方、运输方式、时效、服务范围；
- 成本、底价、合同价、历史成交价、客户目标价（有什么用什么）；
- 加价因素：冷链温控、城配多点、进仓、尾板搬运、偏远超区等（可选）；
- 税费、公司最低毛利要求（可选）。

## 处理

1. 确认计价口径：含税与否；按一票/吨/方/整车，避免混比。
2. 计费重 = max(实际重量, 体积重)；体积重公式以公司规则为准，无规则时写明假设。
3. 拆开基础运费与附加费：燃油、偏远/超区、提送、进仓、保价，以及冷链温控/记录仪、城配多点/时间窗/尾板等。
4. 有依据时按固定结构输出：
   - 成本参考 → 最低可报 → 建议客户价 → 预估毛利（可附毛利率）
   - 附加费是否已包含
   - 风险提示（毛利过低、时效过满、体积重低估、附加费未含、地址/冷链风险）
5. 无依据时：明确还缺价格表/成本/合同价/历史成交中的哪些，**不估假价**。
6. 内部分析与发给客户的报价话术分开写。

## 输出

- 使用了哪些成本与价格依据；
- 各方案毛利、是否贴/破底线；
- 建议客户价与原因；
- 一段可发给客户的报价确认话（外发由用户决定）。

## 文件交付

- **跟进轮同样必须真写入**：用户说「合并/继续/再导出」时，本轮仍要 `write-xlsx`/write，禁止只在正文宣称生成了文件。
- 需要导出业务表时：用 spreadsheets `write-xlsx` / `extract-sheets` 或 write 工具**真正写入**会话目录，并 `verify`；产物卡才会出现。
- **禁止**只在正文写「已生成 xxx.xlsx」却不调用写入工具。
- **禁止**正文以「已生成 **文件名.xlsx**」开场；先结论与要点，再展开。
- 过程脚本与临时 JSON（如 `oma-summary.json`）只放 `os.tmpdir()` / `.opencode/tmp/`，禁止写会话根；不要输出 `文件路径：…`。

## 边界

- 信息严重不全时，先提醒补关键字段，再报价
- 不调度车辆、不承诺运力一定满足（冷链/车型只提示风险）
- 不结账、不对运单财务

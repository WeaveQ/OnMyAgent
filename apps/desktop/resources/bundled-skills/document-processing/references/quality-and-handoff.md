# 质量检查与交付

## 必做检查

1. 确认输出文件存在、可打开，扩展名与实际格式一致。
2. 使用对应专用技能的 `inspect`、`verify`、预览或渲染能力检查结果。
3. 对照用户要求核对文件名、页数或工作表数、关键字段、金额、日期、公式和模板样式。
4. 抽查批量结果的首份、末份和异常项；发现问题时修正后重新检查。
5. 保留原文件，避免把中间文件、缓存和调试产物当成交付物。

## 交付物分层（硬规则）

| 层级 | 放哪里 | 产物卡 |
|------|--------|--------|
| **最终业务文件** | 会话工作区或 `output/` | 是（由 write / extract-sheets / write-xlsx 等溯源） |
| **过程脚本 / 临时 JSON**（含 `oma-summary.json`、`rows.json`） | `os.tmpdir()` 或 `.opencode/tmp/` | 否 |
| **用户上传** | inbox / `session-uploads`（只读） | 否 |

优先使用各格式 runtime 的一等命令（表格：`extract-sheets` / `write-xlsx` / `read`）。只有 runtime 盖不住的复杂编辑才写 helper，且 helper 不得落在会话根目录。

## 给用户的回复

- 先用一两句话说明完成了什么，以及仍需确认的关键内容。
- 有文件产物时，正文只简要说明完成内容；**实际文件只由会话底部的本轮产物卡片展示和打开**。
- **不要**在正文里写 `文件路径：…` 或堆绝对路径——与产物卡重复，用户不需要。
- 只把当前回合新生成的最终文件当交付物；用户输入、临时预览、过程脚本和其他回合文件不属于本轮交付物。
- 自然地推荐最多两个下一步，例如继续核对缺项、按另一模板导出或检查下一批文件。

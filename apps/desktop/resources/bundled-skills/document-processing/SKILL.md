# 文档处理

把这项技能作为办公文件任务的统一入口。先弄清用户最终要拿文件做什么，再按文件类型调用项目已有的专用技能完成操作。本技能负责拆解任务、选择正确工具、衔接多种格式和把关交付质量，不重复实现底层文件引擎。

## 开始前

1. 先读用户已经提供的文件、聊天记录和模板，不让用户重复填写文件里已有的信息。
2. 从上下文能判断用途时直接处理；只有用途会明显影响版式、字段或结果时，才一次询问最关键的两三个问题。
3. 明确用户想要的是查看内容、整理数据、修改原文件、生成新文件、套用模板，还是转换格式。
4. 默认保留原文件，另存为名称清楚的新文件。只有用户明确要求并确认时才覆盖原文件。

## 按格式路由

处理文件前，加载并遵循对应的专用技能：

- `.docx`：使用 `documents`。读取 [references/word.md](references/word.md)。
- `.xlsx`、`.xls`、`.csv`、`.tsv`：使用 `spreadsheets`。读取 [references/spreadsheets.md](references/spreadsheets.md)。
- `.pptx`：使用 `pptx`。读取 [references/presentations.md](references/presentations.md)。
- `.pdf`：使用 `pdf`。读取 [references/pdf.md](references/pdf.md)。

混合文件任务先逐份识别格式和用途，再选择主要交付格式。需要跨格式衔接时，分步骤完成并在每一步检查内容是否丢失。不能由现有技能可靠完成的 OCR、复杂格式转换或旧版二进制 Office 格式处理，应如实说明，并提供可执行的替代办法。

## 通用工作流

### 1. 读懂任务

- 识别文件类型、数量、大小、语言、模板和交付要求。
- 判断是单文件处理、批量处理还是多文件汇总。
- 对合同、账单、报价、证件、回单等内容，区分“文件操作”和“业务判断”；文件技能负责准确处理文档，业务结论仍由当前专家或用户确认。

### 2. 先提取再处理

- 读取已有内容和结构，记录工作表、章节、页面、字段、公式、图片及明显异常。
- 多份文件先建立对应关系，再合并或批量修改。
- 超长文档优先按章节或批次处理，便于检查和重试。

### 3. 制作结果

- 编辑现有模板时保留原有字体、样式、列宽、页边距、页眉页脚和命名习惯。
- 从零创建时，根据用途选择清楚、克制、便于继续编辑的版式。
- 中文内容注意全角标点、字体兼容和中英文混排；不要机械添加空格或首行缩进，优先服从用户模板和原文习惯。
- 批量任务使用脚本或现有文档运行时完成，避免逐份手工重复。

### 4. 校验交付

完成后必须读取 [references/quality-and-handoff.md](references/quality-and-handoff.md)，执行对应格式的检查、预览和交付要求。

**交付分层（摘要）：**

- 业务文件写会话目录；过程脚本只写 `os.tmpdir()` / `.opencode/tmp/`。
- 表格优先 `extract-sheets` / `write-xlsx` / `read`，不要为拆 sheet 在会话根写 `extract_*.cjs`。
- 正文用 `文件路径：业务文件` 硬声明最终物；上传原件与 helper 永不进产物卡。

## 常见任务

- 把聊天、截图、Word、PDF 和多张表里的信息整理成一份可继续使用的 Excel。
- 按用户模板生成报告、合同、报价单、派车单、对账表或汇报材料。
- 合并多张表，统一字段和格式，找出重复、缺失及前后不一致的内容。
- 在保留原样式的前提下批量替换 Word 或 PowerPoint 中的名称、日期和数据。
- 从 PDF 或 Office 文件提取正文、表格、字段和图片，再整理到新的文档中。
- 拆分、合并、排序、旋转或填写 PDF，并检查结果能否正常打开。

## 边界

- 不把“已成功写入文件”等同于“内容正确”；必须检查关键数据、公式、页数和版式。
- 不猜测模糊扫描件、缺失字段、无法解析的公式或业务含义，标记后交给用户确认。
- CSV 给中文 Excel 使用时优先输出 UTF-8 BOM；若用户系统有明确编码要求，以其要求为准。
- 文件预计超过 100 MB 时，提前提醒并优先考虑拆分、压缩或减少嵌入资源。
- 涉及法律效力、付款、开票、最终报价或外部提交的内容，交付前提醒用户做最终业务审核。

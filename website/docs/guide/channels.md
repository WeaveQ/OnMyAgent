# 消息渠道

消息渠道把微信、飞书、Telegram 或 Discord 中的真实消息交给 OnMyAgent，再把 Agent 的结果回复到原会话。它适合远程派活，但不是“显示已连接”就代表完整可用。

产品入口：左侧主栏底部 **消息渠道**。

## 1. 和连接器、Agent 对话有什么区别

| 能力 | 消息渠道 | MCP / 托管连接器 | Agent 对话 |
|------|----------|------------------|------------|
| 谁发起 | 外部 IM 用户 | 当前会话中的 Agent | OnMyAgent 桌面用户 |
| 主要作用 | 接收消息并把回复送回 IM | 调用外部工具、云文档或服务 | 直接驱动本机 CLI / ACP Agent |
| 需要外部账号 | 是 | 视连接器而定 | 通常只需本机 Agent 已安装并登录 |
| 验收标准 | 平台入站 → Agent 执行 → 平台出站 | 工具调用返回真实结果 | 桌面中收到真实 Agent 结果 |

同名能力不一定是同一条链路。例如“飞书消息渠道”负责收发聊天消息，“Lark CLI / 飞书连接器”负责访问飞书文档或开放平台工具。

## 2. 当前渠道

| 渠道 | 连接方式 | 典型前提 | 指南 |
|------|----------|----------|------|
| 微信 | 扫码登录或保存已有账号 | 可扫码的测试微信、网络、允许用户 | [微信](./channels-weixin) |
| 飞书 | WebSocket 长连接或 Webhook | 飞书应用、事件权限、机器人可见范围 | [飞书](./channels-feishu) |
| Telegram | Bot API 长轮询 | Bot Token、可访问 Telegram API、测试用户/群 | [Telegram](./channels-telegram) |
| Discord | Discord Gateway | Bot Token、Gateway intents、服务器/频道权限 | [Discord](./channels-discord) |

聊天渠道注册表里还存在以下占位外壳；它们不是可用渠道：

| 名称 | 当前状态 | 能做什么 |
|------|----------|----------|
| Lark / 企业微信 / 钉钉 | **Stub（transport 尚未实现）** | 可能显示插件卡或设置外壳，但不能建立真实消息收发，也不能用于 E2E 验收 |

这些名称在产品内还可能以“托管工具 / 连接器”出现；那是另一条工具调用链路。不要把同名连接器、正式的飞书渠道与这些 Stub 聊天外壳混为一谈。

## 3. 通用配置流程

1. 打开 **消息渠道**，选择平台。
2. 保存该平台要求的账号或应用凭据。密钥输入框只用于本机配置，不要放进截图、日志或公开文档。
3. 选择工作区、Agent、审批模式和允许访问的目录。
4. 配置允许用户或完成配对。陌生用户不应直接获得 Agent 执行权限。
5. 启动渠道服务，观察连接状态与处理/发送计数。
6. 从真实平台账号发一条带唯一标识的测试消息，等待原会话收到 Agent 回复。

## 4. 配对、授权与审批

- 首次联系的用户可能进入待配对列表；批准或拒绝必须在本机 OnMyAgent 中完成。
- 允许用户应使用专门的测试账号，避免把公共群成员整体放行。
- 审批模式决定 Agent 遇到文件写入、命令等动作时是询问、限制还是继续。
- 平台消息可使用状态、取消、新会话和审批等控制命令；以渠道页面当前显示的命令说明为准。

常见控制语义包括 `#status`、`#cancel`、`#new`、`#approve` 和拒绝审批。正在运行的任务收到新消息时，系统可能提示先查看状态或取消旧任务。

## 5. 怎样才算真实 E2E 成功

一次有效验收必须同时看到：

1. 平台侧发出的真实消息及时间；
2. OnMyAgent 收到对应 sender/chat 和唯一测试标识；
3. 选定 Agent 真实执行并产生完成或审批事件；
4. OnMyAgent 调用该平台的真实发送接口；
5. 同一个平台会话中出现回复。

以下现象都不够：服务显示绿色、WebSocket 为 `open`、本地模拟入站、向本机 Webhook 发送测试 POST、伪造发送函数返回成功，或只看到 OnMyAgent 本地历史。

## 6. 常见问题

| 现象 | 先检查 |
|------|--------|
| 已连接但没有收到消息 | 事件订阅、Bot 可见范围、允许用户、群聊 mention 规则 |
| 收到消息但不回复 | Agent 登录/模型、审批是否待处理、工作区和目录权限 |
| 处理成功但平台没回复 | 平台发送权限、目标 chat、Bot 是否仍在群/频道中 |
| 重复回复或一直忙 | 当前 active run、重连/重试日志、是否重复投递同一事件 |
| 私聊可用、群聊不可用 | 群权限、Gateway intents、mention 或隐私模式 |

## 7. 安全建议

- 使用独立测试 Bot、测试群和最小权限。
- 不在公开视频中展示 Token、App Secret、二维码、邮箱、用户 ID、群 ID 或真实聊天内容。
- 第一次接入先用只读任务，再逐步开放写文件或命令权限。
- 不要在无人值守场景直接启用完全访问或自动批准外发。

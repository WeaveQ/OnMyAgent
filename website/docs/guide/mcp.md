# MCP 与连接器

MCP（Model Context Protocol）把外部工具和资源以标准协议提供给 Agent。OnMyAgent 还支持托管 CLI、云服务插件和消息渠道；它们不是同一层。

## 1. 在哪里配置

主入口：左侧主栏 **市场 → 连接器**。工作区设置、技能详情或首次调用也可能提供配置入口。

## 2. MCP 与其他连接方式

| 类型 | 主要用途 | 详细说明 |
|------|----------|----------|
| MCP | 标准工具/资源协议，可启停和 reload | 本页 |
| 托管连接器 | 安装/登录本机 CLI 或云服务插件 | [连接器与托管工具](./connectors) |
| 消息渠道 | 外部 IM 入站并回复原聊天 | [消息渠道](./channels) |
| BrowserSkill | 外部 `bsk` 与浏览器扩展桥 | [浏览器与 Computer Use](./browser-computer-use) |

## 3. 添加和管理 MCP

1. 打开连接器目录或工作区 MCP 设置。
2. 选择已有条目，或填写自定义 MCP 的命令/地址和必要参数。
3. 保存前确认运行位置、工作目录和环境变量来源。
4. 启用后等待运行时 reload，再在当前会话检查工具列表。
5. 用一个只读调用验证返回内容和目标服务身份。

MCP 的新增、编辑、启停和删除属于配置写操作，可能要求 collaborator 权限与审批，并留下审计/重载事件。

## 4. OAuth 与凭据

- API Key、Token 和 Secret 只走密码型配置或系统凭据存储，不贴进对话。
- OAuth 登录完成后仍要检查 scope 和目标账号。
- **OAuth logout** 只断开对应授权；本机 CLI、缓存或第三方账号数据是否删除取决于该服务。
- 配置变化会触发 reload，正在运行的会话可能需要重新打开或重试。

## 5. 在会话中调用

第一次调用时核对 Agent 准备使用的工具名、账号、资源和写入目标。对于创建、更新、删除、发布、共享或发送操作，保留人工审批并在外部系统中确认真实结果。

工具返回“成功”不等于业务目标完成。例如云文档创建成功后，还要打开真实文档检查内容、权限和链接。

## 6. 公司模式

连接 [OnMyCompany](./company) 后，部分外发和模型调用可能走组织 Gateway。组织策略真相源在服务端；桌面只能消费允许列表，不能在本机放宽 deny 或取回 Gateway 密钥。

## 7. 排障

| 现象 | 检查 |
|------|------|
| 已启用但会话没有工具 | reload 是否完成、当前 workspace、Agent 是否支持 MCP |
| 启动失败 | command/URL、工作目录、环境变量、端口和网络 |
| OAuth 成功仍无权限 | scope、目标组织/账号、资源共享权限 |
| 工具调用超时 | 服务健康、代理、认证过期、Agent active run |
| 桌面有连接器但 Agent 看不到 | 它可能是托管插件，不是 MCP；查看对应连接方式 |

## 8. 安全原则

| 原则 | 说明 |
|------|------|
| 最小权限 | 只开放任务需要的工具、账号和资源 |
| 密钥不进聊天 | 配置页保存，不出现在截图/日志/Git |
| 写操作审批 | 外发、删除、发布和共享先人工确认 |
| 可撤销 | 不再使用时禁用并撤销第三方授权 |
| 真实验收 | 在目标服务中确认结果，不只看本地返回 |

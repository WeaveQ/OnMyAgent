# 审批与权限

本机 Agent 可能读写文件、执行命令或驱动浏览器/桌面。通过会话里的**权限模式**与执行中的**审批确认**控制风险。

## 1. 在哪里切换权限

会话 / 任务输入区**底部工具栏**：

| 控件 | 作用 |
|------|------|
| **权限**（如「默认权限」） | 控制自动执行与敏感步骤是否需你确认 |
| **模型** | 选择当前会话模型（与权限独立） |
| `+` / 附件等 | 附加上下文（与权限模式配合使用） |



![主界面输入区：权限与模型](/images/home-session.png)

<p class="oma-shot-caption">输入区底部可以切换权限模式和模型，不必先打开设置。</p>

更严格的模式会在敏感步骤打断你，而不是静默执行。具体选项文案以输入区下拉为准。

## 2. 三层权限

| 层 | 控制什么 | 例子 |
|----|----------|------|
| 会话访问模式 | 当前 Agent 是否可读、写、执行或在敏感动作前询问 | 默认权限、只读、询问类模式 |
| Agent 原生审批 | Codex/Claude 等底层 Agent 发出的具体请求 | 允许一次、本轮允许、拒绝 |
| 操作系统 / 服务权限 | 应用是否能访问磁盘、屏幕、辅助功能、云账号或组织资源 | macOS TCC、OAuth scope、企业策略 |

放宽其中一层不会自动放宽另外两层。

## 3. 系统级权限

部分能力依赖操作系统授权（磁盘、屏幕录制、辅助功能、麦克风等），在 [设置 → 系统设置](./settings#系统设置) 中查看与引导授权。那是「系统是否允许应用访问」，与会话里的权限模式不同。

## 4. 何时会打断你

常见会要求确认的情况包括：

- 删除 / 覆盖重要文件  
- 执行系统命令  
- 访问未授权路径  
- 其他产品标记为高风险的本机或外发动作  

外发消息、云文档写入、Git push、发布、购买、清空数据和永久删除也应视为需要明确确认的动作，即使某个工具没有自动弹窗。

被打断时先核对：具体命令或工具、绝对路径、目标账号/聊天、影响范围、是否可恢复。然后选择允许一次、当前范围允许或拒绝。不要为了消除重复弹窗就把未知动作设为永久允许。

## 5. 自动批准与无人值守

自动批准只适合隔离工作区、测试账号和经过重复验证的低风险流程。定时任务或消息渠道中的“无人值守”不是跳过审批的理由。

建议先完成：手动运行 → 逐项观察审批 → 固定输入/输出 → 限定账号和目录 → 再考虑只读自动或更窄的自动批准。

## 6. 组织策略

若已连接 [OnMyCompany](../platform/onmycompany)（设置 → **公司**）：

- 桌面应服从组织策略，**不得在本机擅自放宽**  
- 部分外发可能需企业 Gateway  

未连接公司时，仅本机审批与权限模式生效。密钥仍不要贴进聊天，见 [安全与数据](../security)。

## 7. 建议

| 场景 | 建议 |
|------|------|
| 探索 / 草稿 | 可用较宽松权限，但仍指定输出路径 |
| 改生产相关文件 | 收紧权限，逐步确认 |
| 自动化定时任务 | 先手动跑通，再启用；提示词避免无范围删除 |
| 消息渠道 | 只允许测试用户，外发与文件写入保留审批 |
| Computer Use | 先在测试应用验证坐标和控件，不操作支付/生产后台 |
| 远程 / 沙箱 | 核对 token scope 和最终 sandbox backend，不把 `auto` 当成已隔离 |

# 归档、搜索与导入

OnMyAgent 中有两类容易混淆的历史数据：主会话的 Session Archive，以及设置中的已归档任务。它们都能帮助找回工作，但来源和删除语义不同。

## 1. 两类归档

| | Session Archive | 已归档任务 |
|--|-----------------|------------|
| 内容 | 支持来源的会话、消息、用量、分析 | 从任务列表归档的助手/自动化任务 |
| 常见入口 | Agent 管理的会话视图、搜索/分析页面 | 设置 → 数据 → 归档 |
| 数据来源 | OpenCode 与已知 Agent/导入格式 | 当前工作区任务记录 |
| 操作 | 搜索、星标、固定消息、导出、回收站等 | 筛选、恢复、永久删除 |

Personal Local Agent 的对话存储与 OpenCode 主 Session Archive 是独立的；界面看起来相似不代表数据写入同一个数据库。

## 2. 支持来源与限制

- 内置白名单和已知磁盘格式可以被发现并同步。
- 未知 custom agent 不会因为有日志文件就自动进入主归档。
- Claude.ai 和 ChatGPT 数据属于导入源，需要用户先获得导出文件。
- Postgres 与 DuckDB/Quack 后端当前是 blocked 状态，不能按“已连接归档后端”使用或演示。

## 3. 搜索、星标与分析

归档可以提供会话列表、消息搜索、用量、星标、固定消息、分析和 insights。分析结果来自本地归档读模型；同步未完成或来源不支持时，结果可能不完整。

搜索到会话后，先确认来源 Agent、工作区和时间，再恢复或导出，避免把相同标题的其他项目当作目标。

## 4. 导入与导出

1. 从来源产品获得官方导出文件。
2. 在隔离目录保留原始导出备份。
3. 使用 OnMyAgent 导入，检查识别出的来源和数量。
4. 抽查消息顺序、附件和时间。
5. 需要分享时导出 Markdown 等可审阅格式，并再次检查隐私。

导入成功只表示格式被接受；不保证所有第三方元数据、工具调用或附件都能一一还原。

## 5. 回收站与永久删除

- 归档或移到回收站通常可恢复；永久删除不可依赖同一入口恢复。
- 执行批量删除前先按项目/类型筛选并确认数量。
- 不在产品演示中对真实用户数据执行永久删除或清空回收站。
- 删除 Personal 对话、主 Session Archive 和工作区文件是不同动作，应分别确认。

## 6. 数据一致性

主轨 Archive 使用 SQLite、长期 store pool、change bus 和 SSE 保持列表更新。看到短暂旧数据时先等待同步或刷新；不要同时用 Personal runtime 写主 archive 来“补齐”记录。

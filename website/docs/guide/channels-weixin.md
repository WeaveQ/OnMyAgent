# 微信消息渠道

微信渠道通过扫码或已有账号信息连接测试微信，让授权用户从微信向 OnMyAgent 派发任务并在原会话接收回复。

产品入口：**消息渠道 → 微信**。

## 1. 准备

- 一个允许用于测试的微信账号和手机扫码能力；
- OnMyAgent 桌面应用持续运行并能访问微信服务；
- 已可用的工作区、Agent 和模型；
- 一个不会包含真实业务或隐私信息的测试会话。

## 2. 登录并启动

1. 打开微信渠道，选择 **扫码登录**。
2. 用手机微信扫描二维码，并在手机端完成确认。
3. 等待页面显示账号已保存；如页面要求，点击 **检查登录**。
4. 选择工作区、Agent、审批模式与允许目录。
5. 启动渠道服务。

如果使用已有账号信息，请只在产品的密码型输入框中填写；不要把 Token 复制到聊天、截图或问题报告。

## 3. 配对测试用户

1. 从测试微信向已连接账号发送唯一测试文本，例如 `OMA-E2E-日期-序号`。
2. 回到 OnMyAgent 查看待配对用户。
3. 核对脱敏后的用户身份并批准。
4. 再次发送测试任务；第一次未授权的消息不应被当作已完成任务。

## 4. 真实闭环验收

建议任务只要求回复固定格式，不读写真实文件。验收时保存：微信发出时间、OnMyAgent 入站事件、Agent 完成事件、出站发送结果和微信收到回复的时间。

扫码成功、轮询成功或账号状态正常只证明登录链路；必须在微信真实会话中看到 Agent 回复，才算 E2E 成功。

## 5. 文件和媒体

发送或接收文件时，OnMyAgent 仍会执行授权根、文件类型、大小和安全检查。即使运行时记录了某个绝对路径，也不能绕过允许目录。

先用小型、无隐私的测试文件验证；不要用真实合同、客户资料或凭据文件做公开视频素材。

## 6. 排障

| 现象 | 处理 |
|------|------|
| 二维码过期 | 重新生成并扫码，不要复用公开视频中的二维码 |
| 已登录但没有入站 | 检查渠道服务是否运行、允许用户和网络 |
| 一直提示忙 | 用状态命令查看 active run，必要时安全取消后重试 |
| 有本地回复、微信看不到 | 检查真实发送结果、目标用户和账号是否仍在线 |
| 重启后失效 | 检查账号恢复日志；不要仅根据历史记录判断仍在线 |

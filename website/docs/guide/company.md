# 企业连接

企业连接把 OnMyAgent 桌面接入 OnMyCompany，读取组织提供的技能、专家、模型、Gateway 目录和策略。没有企业连接时，本地模式仍应完整可用。

产品入口：**设置 → 工作区 → 公司**。连接成功后，主栏才会出现 **企业**。

## 1. 本地模式与企业模式

| | 本地模式 | 企业连接后 |
|--|----------|------------|
| 是否必须登录 | 否 | 是，需要企业服务和成员会话 |
| 配置根 | `profiles/local` | 成功同步后使用 `profiles/company` 镜像 |
| 策略来源 | 本机产品默认和用户选择 | 组织服务端策略；桌面不得本地放宽 |
| 技能/专家 | 本机安装或个人创建 | 可额外读取组织目录，通常为只读 |
| 凭据 | 用户自己配置 | Gateway 凭据不应返回桌面进程 |

没有 `companyBaseUrl` 和有效成员会话时，OnMyAgent 不应向企业 API 发请求，也不应提前创建 company profile。

## 2. 连接公司

1. 在公司设置中填写组织提供的 OnMyCompany 地址。
2. 输入企业邮箱并完成验证码登录。
3. 等待技能、专家、模型、Gateway 目录和策略同步成功。
4. 返回主界面，确认 **企业** 入口出现。
5. 在企业页查看组织资源；需要管理权限的动作应打开组织管理后台，而不是在桌面绕过策略。

请使用组织管理员提供的正式地址。不要在公开视频中展示企业域名、邮箱、验证码、成员 Token 或策略细节。

## 3. 企业目录

| 区域 | 用途 | 桌面边界 |
|------|------|----------|
| 组织技能 | 在会话中使用组织认可的能力 | 通常只读，不能随意改组织版本 |
| 组织专家 | 使用企业提供的岗位专家 | 生命周期由组织策略决定 |
| Gateway 连接器 | 查看可用外部服务入口 | 密钥不回到桌面；实际调用受网关策略控制 |
| 组织模型 | 使用管理员开放的模型 | 桌面只能消费允许列表 |
| 策略 | 查看 allow/deny、外发和权限限制 | 桌面不得把拒绝改成允许 |

## 4. 配置同步与迁移

- local 和 company 使用同构配置结构，减少两套配置语义漂移。
- 旧的技能和 marketplace 迁移采用复制，不删除原目录。
- 只有企业登录和 pull 成功后才切换到 company profile。
- 断开连接时返回 local profile；已同步的本地镜像可保留，但不应继续被当作实时组织真相源。

## 5. 断开与排障

| 现象 | 检查 |
|------|------|
| 无法连接 | 公司地址 health、网络、邮箱和验证码有效期 |
| 登录成功但企业入口不出现 | profile pull 是否完成、成员会话是否有效 |
| 目录为空 | 组织是否发布资源、当前成员是否在允许范围 |
| 资源可见但不能使用 | 组织策略、Gateway/模型权限、审批要求 |
| 断开后仍看到旧数据 | 重新进入本地 profile；镜像保留不代表仍连接 |

## 6. 当前产品边界

OnMyAgent 当前负责桌面和本地 Server；OnMyCompany 才是企业身份、隔离、策略、审批、审计和 Gateway 的控制面。桌面中的策略展示或本地 evaluator 不能被描述成完整企业控制面。

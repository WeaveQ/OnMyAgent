# 工作区

工作区把会话、文件和 Agent 可访问的目录绑定到一个明确范围。它可以是本机文件夹，也可以是由另一台 OnMyAgent Server 提供的远程工作区。

产品入口：主界面顶部工作区选择器；部分操作也可从命令面板或设置打开。

## 1. 本地与远程工作区

| | 本地工作区 | 远程工作区 |
|--|------------|------------|
| 文件位置 | 当前电脑上的授权文件夹 | 远程 OnMyAgent Server 所在设备 |
| 连接 | 本机 Desktop / Server | Server URL + client token |
| 适合 | 日常办公、私有文件、桌面工具 | 远程机器、长期运行或跨设备访问 |
| 管理权限 | 当前桌面用户 | 取决于 token scope；部分操作需 host/owner 权限 |

远程工作区不等于把整个远程主机暴露出来。OnMyAgent 仍按服务端登记的 workspace 和授权根检查路径。

## 2. 创建本地工作区

1. 打开工作区选择器，选择新建本地工作区。
2. 选择一个专门的文件夹；不要直接把整个主目录、SSH 或云凭据目录作为工作区。
3. 为工作区填写易识别的名称。
4. 等待本地 Server 和 OpenCode 引擎就绪，再创建第一条会话。

OnMyAgent 会在本机维护必要的工作区配置。删除工作区入口与删除原始文件不是同一件事；遇到确认框时仔细核对实际动作。

## 3. 添加远程工作区

1. 准备远程 OnMyAgent Server 地址和 client token。
2. 在新建远程工作区中填写地址、目标 workspace 和认证信息。
3. 运行连接诊断，确认 health、授权范围和 workspace 身份。
4. 打开一个只读文件或新建测试会话，验证实际路径属于预期远程设备。

不要在截图、视频、日志或聊天中展示完整 token。普通 client token 不一定能执行管理、配对或主机级操作。

## 4. 工作区与会话

- 会话 URL 和会话身份都带有 workspace 归属。
- 从命令面板打开会话时，OnMyAgent 会定位该会话所属工作区，而不是默认跳到列表第一个工作区。
- 不存在的 workspace/session 应显示未找到或选择提示，不能静默落到另一个工作区。
- 新建任务、设置、文件和快捷操作都应保持当前 URL 派生的工作区上下文。

## 5. 工作区与文件

- 导入用户文件通常会创建工作区内的副本；原文件是否改变取决于你选择的动作。
- 文件读写、改名、移动和删除受授权根、只读模式、协作者权限、审批和 revision 冲突保护约束。
- 远程工作区的文件上传会通过远程服务完成，不应假定本机路径在远程存在。
- Agent 产物应在 [文件与产物](./files) 中独立验收。

## 6. 重命名、分享与诊断

| 操作 | 说明 |
|------|------|
| 重命名 | 改变 OnMyAgent 中的显示名，不等于重命名磁盘目录 |
| 分享/远程访问 | 创建或展示远程连接信息；注意 token 和有效范围 |
| 诊断 | 检查 Server、引擎、workspace ID、授权和网络 |
| 移除 | 从列表移除前确认是否影响本地配置或远程连接，不要把它当作文件清理工具 |

## 7. 安全建议

- 每个工作区只放当前任务真正需要的文件。
- 演示和自动化使用独立测试工作区。
- 不把 Home、`.ssh`、钥匙串导出、浏览器 Profile 或云凭据目录加入额外挂载。
- 远程连接发现 workspace 或主机身份不符时立即停止，不继续尝试写操作。

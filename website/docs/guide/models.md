# 模型与 BYOK

OnMyAgent **不绑定单一模型厂商**。你在设置里接入自己的密钥或兼容端点（Bring Your Own Key），也可使用本机模型。

## 1. 配置入口

1. 打开 [设置](./settings)（左下角齿轮 → **设置**，或 **⌘ ,**）  
2. 左侧 **工作区 → 模型**（总览里也可点「模型」卡片）  
3. **连接模型服务商** 或 **自定义模型服务商配置**  
4. 填写 API Key、Base URL，或本机模型地址  
5. 回到会话，在输入区右侧选择当前模型  

![设置 · 模型：已连接服务商列表](/images/settings-ai.png)



## 2. 全局模型与本地 Agent 模型

| 配置位置 | 作用 |
|----------|------|
| 设置 → 模型 | 首页 OpenCode 主会话的 Provider、目录和默认选择 |
| Agent 管理 → 某个 Agent → 模型服务商 | 写入该 CLI/ACP Agent 自己认可的 Provider 配置 |
| 会话输入区 | 为当前主会话选择模型和推理档位 |
| Agent 对话输入区 | 只有目标 Agent 支持覆盖时才可切换 |

两处配置不一定互通。设置里连接成功的 Provider，不保证 Codex、Claude Code、Hermes 或自定义 Agent 会自动读取相同配置。

## 3. 会话内切换

输入区右侧可切换模型（不同厂商或推理强度）。新会话默认使用你最近选择或设置中的默认模型。

不同模型支持的上下文、推理档位、工具调用、图片输入和费用不同。切换后检查当前会话实际显示的 Provider/模型，不要只根据显示名推断请求去了哪个端点。

## 4. Ollama 与兼容端点

- Ollama 需要本机服务正在运行、地址可达，并已下载目标模型。
- 自定义 OpenAI-compatible 端点的 models、chat completions 或 responses 兼容度可能不同。
- Base URL 带产品专用版本段时，Agent 管理可能尝试兼容候选端点；最终仍以真实 models 和最小聊天请求为准。
- 本机模型不等于完全离线：网页、连接器或消息平台仍可能联网。

## 5. 建议

| 场景 | 建议 |
|------|------|
| 草稿与头脑风暴 | 较快、成本较低的模型 |
| 长文与复杂规划 | 更强推理模型 |
| 内网 / 离线 | 本机（如 Ollama）或私有化端点 |
| 自动化 / 消息渠道 | 先用低成本测试模型跑真实闭环，再设置预算和失败上限 |
| 敏感资料 | 核对端点、数据政策和组织 Gateway，不只看模型名称 |

## 6. 真实连通验收

“保存成功”或“模型列表可见”不能证明真实生成可用。至少执行一次无敏感信息的最小请求，保存：目标 Provider/模型的脱敏标识、开始/完成时间、真实文本结果、Token/错误摘要，并确认没有回退到另一个模型。

模型调用可能产生 API 费用和配额消耗；批量视频演示或自动化前先限定次数。

## 7. 排障

| 现象 | 处理 |
|------|------|
| 无响应 / 鉴权失败 | 检查 Key、Base URL、代理与额度 |
| 列表为空 | 确认服务商已连接且未禁用 |
| 本机模型连不上 | 确认本地服务已启动，地址与端口正确 |
| Agent 对话仍用旧模型 | 到 Agent 管理检查该 Agent 的独立配置和会话覆盖能力 |
| 列表能拉取但聊天失败 | 检查实际 chat/responses 协议、模型权限和 endpoint 版本 |
| 请求去了错误端点 | 核对 active provider、Base URL、环境变量和运行时重载 |

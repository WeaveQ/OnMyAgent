# Agent 管理

**Agent 管理**用来管理本机可对接的 **智能体舰队（fleet）**：发现已安装 CLI、纳入「我的智能体」、测试连接与修复、配置各 Agent 的 **模型服务商**、查看 **技能识别矩阵**，以及处理相关 **会话归档**。

产品导航文案：左下 **账号菜单 → Agent 管理**（对话页顶部也有 **管理 Agent**）。

## 1. 为什么需要单独一页

| 问题 | Agent 管理做什么 |
|------|------------------|
| 本机装了多个 coding agent，状态不一致 | 统一列表看健康度、筛选离线 / 需登录 / 未安装 |
| 想在 OnMyAgent 里用某 CLI | **纳入管理** 后，才能在 [Agent 对话](./agent-chat) 里稳定选用 |
| 技能装了但某 Agent 识别不到 | 技能矩阵看「哪些 skill 被哪些 Agent 识别」 |
| 模型密钥要按 Agent 写配置 | 为每个 Agent 配置 / 测试 **模型服务商**（BYOK） |
| CLI 路径或环境坏了 | **修复** 覆盖启动命令、环境变量后重测 |

它和主栏 **市场** 不同：市场偏「装专家 / 技能 / 连接器」；Agent 管理偏「管本机 Agent 运行时与目录」。

## 2. 从哪里打开

1. 左下 **账号 / 头像区** 打开菜单  
2. 选择 **Agent 管理**  

也可从 [Agent 对话](./agent-chat) 内的「管理 Agent」类入口跳入（以当前版本界面为准）。

## 3. 顶栏 Tab（概念）

界面常见三个维度（文案以产品为准）：

| Tab | 作用 |
|-----|------|
| **本地** | 「我的智能体」舰队 +「可添加」目录；测试连接、修复、纳入 |
| **技能** | 已识别技能、与各 Agent 的对应关系（技能矩阵） |
| **会话** | 与本地 Agent 相关的会话归档 / 列表视角 |

### 本地：我的智能体

- **已纳入管理的智能体**：可测试连接、修复、用于技能 / MCP / 模型配置。  
- 安装常用智能体后可能 **自动纳入**；也可在下方「可添加」里手动 **纳入管理**。  
- 卡片上常见信息：健康状态、最近检测时间、运行次数等汇总。  

筛选示例：全部 / 健康 / 离线 / 需登录 / 未安装。

### 本地：可添加

- 内置 **Agent 目录**：未安装时主要看安装说明；已安装后可 **纳入「我的智能体」**。  
- 纳入后才能在 Agent 对话中选用，并管理技能与 MCP 相关配置。  

### 自定义 Agent

- 手动注册本机 **CLI / ACP** Agent（ID、名称、命令、参数、环境变量、技能目录等）。  
- 保存后出现在「我的智能体」与本地列表；可启用 / 停用、编辑、删除。  

### 技能 Tab

- 展示本机 / 工作区扫描到的技能，以及被哪些 Agent 识别。  
- 便于排查「技能装了但当前 Agent 用不了」：多半是路径、Agent 原生 skills 目录或纳入状态问题。  

### 会话 Tab

- 本地 Agent 相关会话归档视角；可与 Agent 对话中的历史衔接（具体能力依赖 Agent 是否支持稳定恢复 transcript）。  

这里的会话视图与首页 OpenCode 主 Session Archive 不应混为一谈。未知自定义 Agent 也不会因为产生了日志就自动进入主归档。

## 4. 卡片上常见操作

| 操作 | 说明 |
|------|------|
| **测试连接** | 探测安装、认证与 ACP 链路（离线 / 未安装也可测，用于定位） |
| **纳入管理** | 从「可添加」加入「我的智能体」 |
| **修复** | 覆盖启动命令、环境变量；保存后重测 |
| **配置模型服务商** | 为该 Agent 添加 / 编辑 API 地址、密钥、模型列表；可拉取模型、连通测试 |
| **展开详情** | 查看指标与更多操作 |

### 连接结果含义（摘要）

| 结果 | 含义 |
|------|------|
| 连接正常 | 可对话；可能附带可用模型数量 |
| 需要登录认证 | 先在对应 CLI 完成登录 |
| 未安装 | 可执行文件未找到，先安装再纳入 |
| 连接失败 | 看详情后检查命令、环境、网络与 ACP 参数 |

“找到 CLI”只证明 PATH 或配置中存在候选命令。只有可执行文件启动、认证完成、协议初始化/握手通过，并成功完成真实测试请求后，才能判断 Agent 可用。

## 5. 模型服务商（与 BYOK）

Agent 管理里可为 **每个本地 Agent** 维护其认可的模型提供方。点已保存的服务商会打开 **编辑模型服务商**：左侧 **连接信息**（代号、显示名称、接口地址、访问密钥），右侧 **获取模型** 和 **可用模型**，底部 **保存修改**。逐步说明见 [模型与 BYOK · 编辑模型服务商](./models#edit-model-provider)。

- 接口地址、API Key、显示名  
- 模型列表（可拉取远程列表，或手动加模型 ID）  
- 测试连接 / 指定模型连通性  
- Claude Code 等还可能有角色映射（如 Sonnet / Opus / Haiku 对应实际请求模型）  

这与设置页 [模型与 BYOK](./models) 互补：设置偏 OnMyAgent 全局默认；Agent 管理偏 **写入各 Agent 本机配置** 的路径。

连接测试可能访问真实 Provider 端点并产生少量请求。请使用测试模型和最小配额，不要在演示中显示 API Key、完整 Base URL 查询参数或响应里的敏感账户信息。

## 6. 自定义 Agent 的能力边界

自定义 command 默认只是进程调用，不会自动获得 ACP、流式输出、会话恢复或原生审批。创建时应明确：

- executable、参数和工作目录如何解析；
- 是否启用 ACP，以及握手/事件合同；
- 环境变量来自哪里，哪些值禁止进入日志；
- skills 目录和会话恢复键是否被该 Agent 原生支持；
- 停止任务时能否结束整个子进程树。

只因为自定义 Agent 能输出一段文字，不应把它标成与 Codex/Claude ACP 完全等价。

## 7. 推荐上手顺序

1. 打开 **Agent 管理 → 本地**，看「我的智能体」是否已有条目。  
2. 没有则展开 **可添加**，对已安装 CLI 点 **纳入管理**；未安装的先按引导装 CLI。  
3. 对目标 Agent **测试连接**，处理「需登录 / 未安装 / 失败」。  
4. 需要云端模型时，为该 Agent **配置服务商** 并测通。  
5. 到 **Agent 对话** 选该 Agent 开聊。  
6. 技能异常时到 **技能** Tab 对照矩阵。  

## 8. 与相关功能的边界

| 功能 | 边界 |
|------|------|
| [Agent 对话](./agent-chat) | 用已管理的 Agent **聊天执行** |
| [技能](./skills) / [市场](./overview) | 安装能力包；管理页看 **识别关系** |
| [MCP / 连接](./mcp) | 外部工具连接；可与 Agent 侧扩展一起用 |
| [会话](./sessions) | 首页内置助手任务，不替代本地 CLI Agent 舰队 |

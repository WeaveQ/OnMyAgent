# 自动化

自动化用于**定时**办公任务：日报周报、提醒、汇总等，无需每次手动打开会话。

![自动化：任务列表、模板与调度详情](/images/automation.png)



## 1. 界面结构

| 区域 | 作用 |
|------|------|
| 主栏 **自动** | 进入自动化 |
| 中栏 | **全部任务**、**推荐模板**、已创建的定时任务列表 |
| 右侧 | 当前任务详情：启用状态、提示词、调度时间、运行次数 |
| 顶栏 | **+ 添加** / **从模板添加** |

## 2. 适合的场景

- 每个工作日早晨汇总待办或业务早报  
- 每周五生成周报草稿  
- 固定时间检查某类文件是否更新  

## 3. 新建自动化

1. 打开主栏 **自动**。
2. 选择 **从模板添加** 或 **+ 添加**。
3. 填写名称和提示词；模板内容也要按自己的工作区和目标改写。
4. 选择频率、时区、开始/结束日期或有效期。
5. 绑定工作区、模型、Agent、技能和访问权限。
6. 选择固定输出位置；先保留人工审批，避免首次运行直接外发。
7. 保存并启用，然后先点一次 **立即运行** 验证。

## 4. 频率与时间语义

| 类型 | 用途 | 注意 |
|------|------|------|
| 单次 | 在一个确定时间执行一次 | 错过时间后不会无限补跑 |
| 间隔 | 每隔固定时长重复 | 先确认频率不会造成成本或消息噪音 |
| 每周计划 | 指定星期与时间 | 时区和设备休眠会影响触发 |

普通周期任务只有有限的到期认领宽限；当前运行时大约在计划时间后的 2 分钟窗口内领取。电脑关机、深度睡眠、Server 停止或任务被长时间阻塞时，可能错过一次执行。

自动化不是云端保证送达的调度服务。需要强保证时，应把 Orchestrator/Server 部署在持续在线的受控机器上，并监控真实运行历史。

## 5. 模型、Agent 与权限

- 必须为任务选择可用模型，或确保工作区默认模型可用。
- Agent 和技能应与普通会话里已经跑通的组合一致。
- 权限模式会影响写文件、命令、外发和审批；无人值守不代表应使用完全访问。
- 绑定的工作区决定文件读写范围；不要在提示词里依赖另一台机器才存在的路径。

## 6. 立即运行、停止与暂停

| 操作 | 影响 |
|------|------|
| 立即运行 | 立刻创建一次真实 run，不改变后续计划 |
| 停止当前运行 | 取消正在执行的这一轮，计划仍可能保持启用 |
| 暂停 / 停用计划 | 阻止新的计划运行，不一定终止已经开始的 run |
| 恢复 | 重新允许后续计划触发 |
| 归档 | 从主要列表移出，历史和删除边界以确认框为准 |

如果任务已经写出部分文件，停止后要检查半成品，不要默认系统自动回滚。

## 7. 运行目录、历史与超时

每次 Server 自动化运行会建立独立任务目录，并写入任务说明和执行结果等记录。等待单次任务完成有上限，当前最长约 2 小时；超时不等于底层进程一定安全结束，应同时检查状态和产物。

在运行历史中核对：计划触发时间、实际开始/结束时间、使用的模型/Agent、完成状态、错误和产物。对文件类结果仍需到 [文件与产物](./files) 独立打开。

## 8. 风险与常见问题

| 现象 | 检查 |
|------|------|
| 到点没有运行 | Server 是否持续运行、设备休眠、计划时区、是否错过宽限窗口 |
| 保存后提示模型缺失 | 绑定模型或默认模型是否仍可用、Provider 认证 |
| 一直运行或超时 | Agent active run、审批是否等待、外部工具/网络 |
| 运行成功但没有目标产物 | 提示词、输出路径、工作区归属、执行结果文件 |
| 重复发送消息 | 调度频率、重试、是否有两个实例运行同一计划 |

涉及外发、删除、发布、真实云数据或付费 API 时，先在测试账号和小样本运行。稳定后再逐步放宽。

## 9. 建议

- 先在普通 [会话](./sessions) 里手动跑通同一提示词，再交给自动化  
- 输出路径固定，便于查找和 diff。
- 记录预期产物、最长运行时间、失败通知和人工接管方式。
- 涉及外发或高风险动作时配合 [审批与权限](./approvals)。

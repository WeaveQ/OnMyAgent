# 飞书消息渠道

飞书渠道让企业自建应用通过 WebSocket 长连接或 Webhook 把消息交给 OnMyAgent，并由机器人回复原聊天。

产品入口：**消息渠道 → 飞书**。

## 1. 选择连接方式

| 方式 | 适合 | 额外条件 |
|------|------|----------|
| WebSocket 长连接 | 本机运行、没有公网回调地址 | 飞书应用启用长连接事件接收，网络可连接开放平台 |
| Webhook 回调 | 已有稳定公网入口或内网穿透 | 飞书能访问配置的 URL；本机监听地址本身通常不能被公网访问 |

WebSocket 显示 `open` 只表示传输连接存在，不能证明事件权限、消息分发和机器人回复均已成功。

## 2. 飞书应用准备

1. 在飞书开放平台创建企业自建应用并启用机器人。
2. 配置接收消息事件和机器人发送消息所需权限。
3. 把应用发布到测试范围，并把机器人加入测试私聊或群聊。
4. 准备 App ID 与 App Secret；Webhook 模式还可能使用 Verification Token 和 Encrypt Key。

权限和事件名称可能随飞书平台更新；以开放平台当前控制台为准。只给测试应用最小范围，不要直接授权整个生产组织。

## 3. OnMyAgent 配置

1. 填写 App ID 与 App Secret。
2. 选择 **WebSocket 长连接** 或 **Webhook 回调**。
3. Webhook 模式下确认 host、port 与 path，并把真正可公网访问的地址配置到飞书；页面中的 `127.0.0.1` 只能被本机访问。
4. 选择工作区、Agent、审批模式和允许用户。
5. 保存并启动服务。

## 4. 群聊和配对

- 群聊可能要求 mention 机器人；是否必须 mention 取决于应用事件配置和当前渠道策略。
- 首次发信的用户可能需要在 OnMyAgent 本机配对批准。
- 应用可见范围、群成员身份和允许用户必须同时满足。
- 不要把“收到了事件”误认为“消息已交给正确 Agent”；同时核对绑定工作区与 Agent。

## 5. 真实闭环验收

从飞书测试聊天发送带唯一标识的消息，确认 OnMyAgent 收到真实 `im.message.receive_v1` 类事件、Agent 完成、调用飞书真实发送接口，并在同一聊天中看到机器人回复。

以下证据不能单独通过验收：WebSocket `open`、本地历史有消息、处理计数增加、向本地 Webhook 手工 POST、Fake WebSocket、Fake OpenAPI send。

## 6. 排障

| 现象 | 检查 |
|------|------|
| 长连接已开但无入站 | 事件订阅方式、应用发布状态、可见范围、消息事件权限 |
| 私聊可用群聊不可用 | 机器人是否入群、mention、群事件权限 |
| 入站正常但不执行 | 配对/允许用户、Agent 和模型、审批队列 |
| 执行完成但无回复 | 发送消息权限、目标 chat、应用发布版本 |
| Webhook 校验失败 | 公网可达性、Verification Token、Encrypt Key、回调路径 |

# 文件模块产品说明书

> **状态**：产品 SoT v0.3（**P0 壳已落地**：三 Tab + 用户上传复制导入 + 任务文件工作区浏览器 + 专家诚实空态；C1 连删 / C5 归档对等已锁定；§13 待决与 P1 写路径打标仍有效）
> **范围**：主栏「文件」页（`?view=files`）及产生、展示、会话生命周期
> **不在本文**：网盘/云同步完整产品、跨工作区全局检索、任意本机路径直改（高级链接模式）
> **代码入口**：`apps/app/src/react-app/domains/workspace/workspace-files-*.tsx`

---

## 1. 模块定位

**文件**是用户查看与管理「工作区相关资料与 AI 产物」的统一入口，按**来源**分三类，而不是按文件类型（pdf / md）分栏。

用户应能快速回答：

1. 这是我上传的吗？
2. 这是首页临时任务聊出来的吗？
3. 这是某个专家任务产出的吗？

**原则：**

- 改**展示与归因**，不改变任务/专家/工具「能否写文件」的主流程。
- 写入侧最多增加**来源标记**（或轻量目录约定）。
- 文件默认跟**工作区**走，不跟会话「陪葬」。

---

## 2. 信息架构（三 Tab）

进入主栏 **文件** 后，顶部为三个来源 Tab（free-float 选中 pill；实现使用设计系统 NavTab 反色填充，**禁止**依赖会被暗色主题改写的裸 `bg-white`）。

| Tab | 中文名 | 英文 | 含义 |
|---|---|---|---|
| A | **用户上传** | Uploads | 用户主动导入、落入**当前工作区**的资料（工作区**副本**） |
| B | **任务文件** | Task files | **首页 / 助理**下**临时任务**对话产生的文件 |
| C | **专家文件** | Expert files | **专家**会话产生的文件，按专家归类；原「工作空间」式归档并入本 Tab |

页标题与主栏短名统一为 **文件**（i18n：`files.title` / `nav.files` 应对齐，避免「我的文件」双轨）。

默认打开 Tab：**用户上传**（deep link `?view=files` 无子参数时落此 Tab）。

## 3. 用户上传：导入与编辑模型

### 3.1 是什么

- 用户通过 Files 页上传、对话附件、拖拽等方式选择的本机文件。
- **目的**：作为资料进入工作区，供对话引用、查看、管理。
- **不是**：助理/专家自动生成的产物。

### 3.2 导入 = 复制进工作区（默认且唯一主路径）

1. 用户选择本机文件（系统选择器 / 拖拽）。
2. **复制**到当前工作区约定目录（建议统一：`uploads/` 或 inbox 规范路径，**全产品只定一种**）。
3. 打标：`source = user_upload`；可选记录 `originalName`、`importedAt`、`sourcePath`（本机原路径，仅作提示/写回，可失效）。
4. 对话附件、Files「用户上传」、@ 引用，一律指向**工作区内路径**。

**禁止**将「仅保存本机绝对路径、不复制」作为默认上传模型。

### 3.3 谁改什么（关键语义）

| 对象 | 谁改 | 说明 |
|---|---|---|
| **工作区副本** | 用户预览编辑 / **AI 工具写入** | 对话与 Files 的**唯一真相** |
| **本机原文件** | **默认不改** | 导入后与工作区脱钩 |

用户感知的「AI 改了文件」= **AI 改的是工作区副本**，不是直接改本机原件。

### 3.4 双份文件的体验与写回

导入后可能出现：工作区副本已更新，本机原件仍旧。

**必做：**

- 上传成功提示：已保存到工作区；编辑只影响工作区副本，不会自动改本机原文件。
- 列表/详情可展示来源：`来自：…`（`sourcePath` 失效则隐藏）。

**可选（P2）：写回本机**

- 条件：副本有修改且 `sourcePath` 仍有效、可写。
- 交互：明确按钮或关闭时询问「是否覆盖本机原文件？」；失败则「原文件已移动/删除，请另存为」。
- **禁止**默认静默覆盖本机原件。

### 3.5 与会话生命周期

- 用户上传**不绑定**会话。
- 删会话、归档会话均**不影响**用户上传列表中的条目。
- 删会话时若勾选「同时删除生成的文件」，**默认不包含** `user_upload` 文件。

### 3.6 对话附件

- 与 Files 上传使用**同一导入模型**（复制 + `user_upload`）。
- 出现在「用户上传」；若在临时任务中附带，可在任务上下文中引用，但**来源归属仍是用户上传**，不因任务结束而改源。

## 4. 任务文件

### 4.1 是什么

在**首页（助理）**中，**临时任务**对话过程中产生/写出的文件。

### 4.2 「临时任务」判定（v0.2 暂定，实现按此打标）

同时满足：

1. 会话处于**助理 / 首页**模式（非专家身份）；
2. 会话类型为产品定义的**临时任务**（无专家 agent 绑定；与「专家会话」互斥）；
3. 文件由该会话上下文中的工具/运行时写出（含 Agent 写入工作区）。

> 若代码里尚无统一 `sessionKind`，实现前在工程中落地等价字段，并回写本节。

**当前不包含（扩展需改说明书）：**

- 专家会话产物；
- 本地编码 Agent / 自动化任务产物（见 §13）；
- 用户上传副本。

### 4.3 与「选择文件夹 / 工作区」

- 任务可绑定工作区或用户选择的目录；产物落在该上下文的路径下。
- **磁盘上只有一份 path**；「任务文件」是按来源过滤的**视图**，不是第二份拷贝。
- 在工作区目录中改名/删除，与 Files 列表同步（同一文件）。

### 4.4 展示

- 列表列：名称 · 大小 · 最近使用 · 操作（可选：所属任务名）。
- 最近使用默认按 **mtime（修改时间）**。

---

## 5. 专家文件

### 5.1 是什么

**专家**会话产生的文件。
归类依据：**谁的会话写的（专家会话）**，不是路径是否在 workspace 内。

### 5.2 展示（v1 锁定）

- **默认导航：L0 → L1**
  - **L0**：按专家分组/文件夹（名称、最近使用等）；
  - **L1**：该专家下文件列表（名称 · 大小 · 最近使用 · 操作；可带任务名）。
- 平铺「全部专家文件 + 专家列」作为 **P2** 增强，不与 L0/L1 并列为 v1 必做。
- 承接原参考「工作空间」按专家归档的体验；**不再单独设「工作空间」Tab**。

### 5.3 专家被移除

- 文件保留；展示名用快照；可标 **「专家已移除」**（与孤儿会话同类处理）。

## 6. 页面结构与交互

### 6.1 页头

- 标题：**文件**
- 三个来源 Tab
- 当前 Tab 一行说明，例如：
  - 用户上传：已导入工作区的资料（编辑只影响工作区副本）。
  - 任务文件：首页临时任务产生的内容。
  - 专家文件：专家任务产物，可按专家浏览。
- 右侧搜索：placeholder 随 Tab 变化。

### 6.2 列表与操作

- 行操作（⋯）：预览/打开、在文件夹中显示（桌面端，指工作区路径）、复制路径、删除、添加到当前任务（若已有能力）等。
- 用户上传在具备 `sourcePath` 时可增加「写回本机」（P2）。
- 选中行浅底；**loading 时不得显示「暂无」类空态**。

### 6.3 预览

- 沿用现有 preview 规则（可预览内联；Office 等按既有策略）。

## 7. 生命周期

### 7.1 删除会话（C1 已锁定）

| 对象 | 默认行为 |
|---|---|
| 对话 / 消息 | 按现有删除逻辑永久删除 |
| 该会话 **生成** 的文件（`assistant_task` / `expert`，落在 `tasks/{sessionId}/`、`experts/{agent}/{sessionId}/` 等可归因根下） | **默认一并删除**（确认文案明确提示「将删除该会话生成的工作区文件」） |
| **用户上传**（`uploads/`） | **不在**连删范围内 |

**二次确认（禁止静默）：**

- 永久删除前必须确认；文案须写明**会删除会话生成的工作区文件**（不可恢复）。
- 不提供「默认保留生成文件」的静默路径（与 v0.1 草案不同，以 C1 为准）。

**连删约束：**

- 仅删除可归因到该 `sessionId` 的 layout 根（及元数据 `directory` 解析出的根）下的文件。
- 归因失败时仍展示「会删除生成文件」提醒；磁盘侧 best-effort（缺路径不静默假成功掩盖）。
- 不包含 `user_upload`。

### 7.2 归档会话（C5：专家与任务对等）

| 对象 | 默认行为 |
|---|---|
| 对话 | 软归档：离开 live 列表，进入设置「已归档」；专家与助理任务同一 store（`category: expert`） |
| 文件 | **一律保留**路径与内容，不挪、不删（归档 ≠ 永久删除） |
| Files | **默认仍显示** |
| 恢复 | 设置归档列表「取消归档」回到 live；永久删除走 §7.1 |

归档 ≠ 删文件，≠ 从 Files 消失。

### 7.3 删除文件（Files 内）

- 用户主动删单文件/多文件：确认后删除；与会话是否存在无关。
- 三类 Tab 均可单独删文件。

## 8. 数据与归因

### 8.1 写入打标（P1 起对新文件强制）

| 字段 | 说明 |
|---|---|
| `source` | `user_upload` \| `assistant_task` \| `expert` |
| `sessionId` | 可空；会话删除后置空或 `sessionDeleted: true` |
| `agentId` / 展示名快照 | 专家归类与展示 |
| `createdAt` / `mtime` | 排序；「最近使用」默认 mtime |
| `sourcePath` | 仅用户上传可选；本机原路径 |

打标规则：

- 导入/对话附件 → `user_upload`
- 首页临时任务会话写文件 → `assistant_task`
- 专家会话写文件 → `expert`

### 8.2 读取

- Tab 按 `source` 过滤（或与目录约定等价）。
- 专家 L0：`groupBy(agentId | 展示名快照)`。
- 会话删除：更新索引，默认不 unlink。

### 8.3 工作区目录约定（v1 落盘）

工作区根下固定四分区（与三 Tab 对齐；`projects/` 在任务 Tab 一并展示）：

```text
workspace/
  uploads/                         # 用户导入副本（Files → 用户上传）
  tasks/                           # 首页临时任务 / 自动化任务产物（→ 任务文件）
    自动化任务-YYYY-MM-DD-HH-mm-ss/
  experts/                         # 专家归档（→ 专家文件）
    {展示名-slug}/
      {sessionKey}/
  projects/                        # 用户自建项目夹（→ 任务文件，非专家）
```

| 来源 | 写入路径 | Files Tab |
|---|---|---|
| 用户上传 / 对话附件 | `uploads/`（inbox 传输后落此逻辑区） | 用户上传 |
| 首页临时任务 / 自动化 | `tasks/…` | 任务文件 |
| 专家会话（未选手动文件夹） | `experts/{agentSegment}/{sessionKey}/` | 专家文件 |
| 用户自建项目 | `projects/…` 或用户显式选择的路径 | 任务文件 |

**历史清洗：** 扁平根下的专家夹 / `自动化任务-*` / 散落文件，用 `scripts/migrate-workspace-files-layout.mjs` 迁入上表；未识别的目录进 `projects/`。

### 8.3 历史文件（backfill / 兼容）

- **不删内容**。
- **P0 兼容**：未打标的历史工作区文件 → 在 **任务文件** Tab 中通过工作区目录浏览器访问（保证升级后仍能看到旧文件）。
- **专家文件** Tab 在写入打标上线前保持诚实空态，**禁止**把未打标历史静默标成专家。
- **P1+**：按 `source` 过滤后，任务/专家各归其位；可选「未分类」弱提示。

### 8.4 对产生侧的影响

- 不改变写文件主流程与能力。
- 最多附加元数据 / 轻量目录约定。
- 会话删除/归档钩子以更新索引为主。

## 10. 权限与范围

- 以**当前工作区**为主。
- 文件归属写入时的工作区；切换工作区后，在**原工作区** Files 中仍可见（不随 UI 切换「带走」）。
- 桌面端「在文件夹中显示」指向**工作区路径**。
- 网盘/团队共享：非 v1。

## 12. 成功标准

1. 三类来源与 Tab 内容一致，用户能理解「AI 改的是工作区副本」。
2. 新上传、新任务产物、新专家产物出现在正确 Tab。
3. 删会话默认留生成文件，可标孤儿；连删不含用户上传、不含共享 path 误删。
4. 归档会话后文件默认可在 Files 见到，可标已归档。
5. 用户上传不受会话删/归档影响。
6. Loading ≠ 空态；选中 pill 用设计系统 token。

## 16. 一句话总结

**三分来源看文件：用户上传是工作区副本（AI 只改副本、本机原件默认不动）；任务文件来自首页临时任务；专家文件按专家归档。文件跟工作区、不跟会话陪葬；删会话/归档默认不删文件；产生主流程不动，只补来源与展示。**

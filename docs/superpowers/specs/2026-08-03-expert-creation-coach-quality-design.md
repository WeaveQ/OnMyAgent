# 专家创建教练质量工作流设计

## 背景

创建专家页面目前可以通过“专家教练”收集用户意图并向右侧草稿建议字段，但教练主要围绕简单提示词给出泛化建议。这样生成的角色提示词可能缺少明确的能力边界、执行流程、交付结构和沟通约束，难以稳定产出一个真正可用的专家。

项目内置的 `expert-manager` 技能已经定义了专家包的核心质量要求：角色定义、核心能力、工作流程、输出规范、注意事项，以及展示信息、技能选择和校验流程。本设计把其中适用于创建页面的质量要求带入教练对话，同时保持当前创建页面的数据结构和用户操作习惯。

## 目标

1. 让专家教练按照可执行的阶段化流程收集信息，而不是只改写一段泛化提示词。
2. 让角色提示词在应用到右侧前具备稳定的 Markdown 结构和完整章节。
3. 让当前 SessionSurface 路径和旧版回退路径使用同一套质量规则。
4. 保留当前建议应用体验：空字段自动填入，已有内容出现差异时由用户确认覆盖。
5. 只使用当前技能目录中已启用的技能 ID，不编造技能或能力。

## 非目标

- 不新增用户可见的表单字段。
- 不改变 `AgentWizardDraft`、专家保存格式或专家召唤流程。
- 不在创建页实现完整的专家包初始化、头像生成、校验、注册和打包流水线；这些仍属于 `expert-manager` 技能的执行范围。
- 不要求模型每轮都生成完整版本；信息不足时继续澄清是正常结果。

## 方案

采用“结构化教练工作流 + 现有字段兼容”方案。新增一个 agents 域内的纯规则模块，作为教练提示词和建议解析的共同契约。它是系统内部实现，不会在界面上显示“质量契约”，也不会增加用户填写成本。

### 教练阶段

教练按以下顺序推进，每轮最多追问一个关键问题：

1. **定位**：确认服务对象、使用场景、任务触发条件和核心交付物。
2. **能力**：明确专家要完成的能力，以及判断质量的依据。
3. **规则**：明确信息不足时的处理、假设与确认、取舍和决策原则。
4. **边界**：明确禁止行为、越权范围、事实与不确定性处理。
5. **流程**：按执行顺序定义从输入澄清到结果交付的步骤。
6. **交付**：定义不同任务的内容结构、格式、检查项和完成标准。
7. **沟通**：定义语言、语气、确认节奏和输出偏好。

信息不足时，教练不返回完整建议版本，而是提出下一项最有价值的问题，并可给出具体选项或假设供用户确认。

### 角色提示词结构

完整版本的 `userNote` 使用以下固定章节，标题允许 `##章节` 和 `## 章节` 两种空格写法：

```md
## 专家简介
## 核心能力
## 关键规则
## 禁止行为
## 工作流程
## 内容结构
## 沟通风格
```

每个章节必须有实质正文；正文不能是空白、`[TODO]` 或仅重复章节标题。内容应描述可执行动作、判断标准或边界，而不是只写“专业地完成任务”一类泛化形容词。

### 建议数据流

现有字段协议继续使用：

- `name`
- `description`
- `userNote`
- `agentMemory`
- `skillIds`

当前聊天路径的 `expert-update` 解析和旧版结构化输出路径都调用同一套角色提示词校验。完整 `userNote` 才能作为完整角色版本应用；不完整 `userNote` 不覆盖用户已有内容，其他独立字段仍可遵循现有空字段自动填入和差异确认规则。

技能目录在每轮提示中提供已启用技能的 ID、名称和描述。教练只能提出目录中的 ID，并说明技能对应的工作类型；解析层继续过滤未知或未启用 ID。

## 组件与代码边界

预计改动集中在 agents 域：

- 新增角色提示词质量契约纯模块，提供章节定义、完整性校验和教练工作流说明。
- 更新 `expert-creation-coach-agent`，供当前 SessionSurface 教练使用。
- 更新 `expert-creation-coach-model`，供旧版/回退路径和结构化输出使用。
- 更新建议解析，使不完整角色提示词不会覆盖右侧已有内容。
- 更新英文、简体中文、繁体中文内置教练说明，保证缓存缺失时的内置角色也遵循新流程。
- 为质量契约、两个提示词构建器和两条解析路径增加纯函数测试。

不修改 session archive、专家注册/召唤逻辑和用户可见页面布局。

## 异常处理

- 模型返回缺章节、空章节或模板占位符：视为尚未准备好，继续追问，不显示系统错误。
- 模型返回未知技能：保留其他有效字段，过滤未知技能 ID。
- 模型返回完整角色提示词但与右侧已有内容冲突：沿用现有差异提示和用户确认覆盖机制。
- 模型请求失败：沿用现有重试、失败提示和会话恢复行为，不改变临时会话生命周期。

## 验收与测试

1. 质量契约测试覆盖完整章节、缺章节、空章节、占位符和两种标题空格写法。
2. 建议解析测试覆盖完整角色提示词通过、不完整角色提示词不覆盖已有内容、独立字段仍可同步。
3. 结构化输出路径测试覆盖相同的完整性要求。
4. 现有专家创建生命周期、技能过滤和差异确认测试继续通过。
5. 运行 app 类型检查、专项测试、生产构建、文件大小、边界、禁止类型、i18n 和 `git diff --check`。

## 已确认的产品决策

- 采用结构化教练工作流，不增加用户可见表单字段。
- 角色提示词必须以七章节结构为完整版本门槛。
- 空字段自动填入，已有字段覆盖前由用户确认。
- 头像不属于角色提示词完整性门槛。
